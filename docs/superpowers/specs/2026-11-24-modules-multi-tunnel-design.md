# Модули на флешке и несколько туннелей одновременно — дизайн

Дата: 2026-11-24. Статус: черновик на согласование.

## Зачем

Базовый пакет (TrustTunnel, Zapret, панель, ~18 МБ) помещается в `/data` и остаётся основой. Другие протоколы
(VLESS/Reality, Hysteria2, AmneziaWG и т. п.) в `/data` не помещаются: их движки весят 10–30 МБ. Пользователь хочет
ставить их **модулями** на подключённую флешку (или в `/data`, если хватает места) и пользоваться протоколами
**одновременно**: TrustTunnel — один из протоколов на выбор, а не основной и не запасной. Разные сайты и устройства
могут идти через разные серверы с разными протоколами.

## Цели

1. Пакет сам находит подключённые накопители (USB) и показывает их свободное место.
2. Новая страница панели **«Модули»**: список доступных модулей, размер, куда можно поставить (флешка / `/data`),
   кнопка установки — активна, только если места хватает; установленные модули — версия, где лежат, состояние,
   обновление, удаление.
3. Несколько серверов (профилей) одновременно, у каждого свой протокол; правила «Сайтов» и «Устройств» выбирают сервер.
4. Пакет следит за флешкой: если модуль используется, а флешка недоступна — уведомление (Telegram, если настроен,
   и баннер в панели); когда флешка вернулась — модуль запускается снова сам, о возврате тоже уведомление.
5. Без модулей и без второго сервера всё работает ровно как сейчас (нулевая регрессия для текущей установки).

## Не цели

- Модуль ядра AmneziaWG (под ядро стока не собрать) — только userspace `amneziawg-go`.
- Хранение настроек/секретов на флешке — они остаются в `/data` (как и сейчас с `--store`).
- Перенос базового пакета на флешку автоматически (ручной `--store` остаётся как есть).
- Сторонние модули от кого угодно: ставятся только модули, подписанные нашим ключом релиза.

## Антицели (провал, даже если «работает»)

- Сломать QoS/родительский контроль/прошивочные функции захватом чужих битов метки без проверки.
- Падение TrustTunnel или всего VPN из‑за пропажи флешки с модулем.
- Утечка трафика правил модульного сервера в обход при недоступном модуле, если политика правила — «блокировать».
- Заметное замедление существующего TrustTunnel (лишнее звено userspace на его пути).

## Ограничения и факты

- Карта битов `skb->mark` стока (`miqosd_init.sh`): QoS `0xffff8000`, mwan3 `0x3f00`, плагин UU `0xf0`,
  родительский контроль `0xf`; свободен только `0x4000` (используется пакетом). nfqws2 пакета использует `0x40000000`.
- На роутере пользователя (2026-11-24) `iptables-save` показывает только наши метки (`0x4000`, `0x40000000`),
  процессов UU/parentctrl/mwan3 нет → биты `0xf0` фактически свободны.
- Флешки монтирует прошивка (`/mnt/usb-*`, также `/extdisks/sd*`); файловая система может быть FAT/exFAT/NTFS — без
  прав исполнения и симлинков.
- Движки сейчас запускаются из RAM (`/tmp`) — бюджет `/tmp` проверяется при установке.
- BusyBox ash 1.25, тесты только в лаборатории (qemu-user), на реальном роутере проверяет пользователь.

## Подходы (рассмотрены)

**A. Один распределитель.** sing-box владеет `mitt0`, весь VPN-трафик идёт в него, он раскладывает по серверам;
TrustTunnel — SOCKS-выход sing-box. Один бит хватает, серверов сколько угодно. Минусы: лишнее звено на пути TrustTunnel
(двойная обработка TCP, потолок скорости ниже), неизвестна поддержка UDP в SOCKS-входе TrustTunnel (риск для игр),
пропажа флешки роняет весь VPN без отдельного возврата к прямому режиму.

**B. Свой туннель и своя метка на каждый сервер — ВЫБРАН пользователем.** Каждый сервер поднимает свой TUN-интерфейс,
трафик правила помечается номером туннеля, `ip rule` уводит его в таблицу этого туннеля. Без посредника, максимум
скорости, отказ одного туннеля не трогает остальные. Требует занять биты `0xf0` (плагин UU), что безопасно, пока UU не
используется, — пакет это проверяет.

**C. Разделение только по устройствам** (`ip rule from <ip>`). Отброшен: не умеет «этот сайт через другой протокол».

## Решения (как будет устроено)

### 1. Маршрутизация (вариант B)

- Бит `0x4000` остаётся «трафик в туннель». Номер туннеля — в нибле `0xf0` (значения 0–15).
- **Один туннель** (сейчас у всех): маска остаётся `0x4000/0x4000` (`fmt_mark(NF_MARK, NF_MARK)` в `plan.rs`), таблица
  3100, ни одно правило не меняется, биты `0xf0` не трогаются — UU/прошивка ими могут пользоваться.
- **Два и больше туннелей**: маска `0x40f0`; туннель n → `--set-xmark 0x40n0/0x40f0`,
  `ip rule fwmark 0x40n0/0x40f0 lookup 3100+n` (приоритеты в зоне 3000–3199), в таблице `default dev mitt<n>` или
  `unreachable`/обход по политике отказа этого профиля. Переход 1↔N туннелей — обычное атомарное переприменение цепочек
  по хэшу (как сейчас).
- Индекс туннеля — стабильный номер профиля, хранится в конфиге: существующий профиль получает 0 (таблица 3100,
  `mitt0`), новые — первый свободный 1..15. Индекс 0 не означает «главный»: при удалении профиля 0 его номер
  освобождается, остальные номера не сдвигаются. Все жёсткие `mitt0` в коде заменяются на интерфейс по индексу.
- **Поле номера туннеля выбирается из двух наборов**: основной — `0xf0` (резерв плагина UU), запасной — `0x0f00`
  (младшая половина резерва mwan3 `0x3f00`; mwan3 работает только при втором WAN). Номер n кодируется как
  `n << shift` (shift 4 или 8), маска правил — `0x4000 | field` (`0x40f0` или `0x4f00`). Выбранный набор
  записывается в состояние, панель показывает, какой используется.
- Проверка владения — двухступенчатая: (1) как сейчас, чужие правила на `0x4000` → отказ всего применения;
  (2) поле номера: если на `0xf0` есть чужие правила/`ip rule`/метки — берётся `0x0f00`; если заняты оба набора —
  применяется только туннель 0 (маска `0x4000`), туннели 1..15 снимаются, их правила действуют по политике отказа своих
  профилей, ошибка в панели «биты для нескольких туннелей заняты прошивкой (плагин UU и резервный WAN)» и уведомление.
  Проверка — при применении и в периодическом тике; конфликт, возникший при работе, приводит к атомарному
  переприменению на другом наборе (или снятию туннелей 1..15, если свободного нет) с уведомлением. Чужие биты не делим.
- Политика отказа — у каждого профиля своя (`Profile.on_failure` уже есть в модели; глобальный `PolicySpec.fail_open`
  становится по профилю: защитный маршрут в таблице каждого туннеля).
- DNS роутера для сайтов через VPN (`dns_resolver`, защищённый DNS `--device mitt0 --mark 0x4000`) идёт через
  выбранный «DNS-туннель», по умолчанию — профиль с наименьшим индексом; если он не поднят — через следующий поднятый.
  Выбор — в «Настройки» → «Сеть и DNS» (появляется, только когда серверов больше одного).
- IPv6 через VPN — аналогично на `ip -6 rule`, для туннелей, движок которых даёт IPv6.
- Снимаем ограничение `too_many_profiles` (validate.rs): до 16 профилей; лимит связан с ниблом.

### 2. Профили и протоколы

- `ProfileKind` расширяется: `trusttunnel`, `vless`, `hysteria2`, `trojan`, `shadowsocks` (движок sing-box),
  `amneziawg` (движок amneziawg-go). Каждый профиль получает индекс туннеля (стабильный, хранится в конфиге), свой
  каталог рендера и свой процесс. Для протоколов sing-box — по процессу на профиль с одним `tun`-входом (`mitt<n>`) и
  одним выходом; это проще отказоустойчивости и диагностики ценой RAM (~20–30 МБ на процесс). Решение строителя:
  можно объединить в один процесс, если проверка покажет, что sing-box надёжно держит несколько tun-входов и
  перезапуск одного профиля не рвёт остальные.
- Ввод сервера: ссылка (`vless://`, `hysteria2://`/`hy2://`, `trojan://`, `ss://`), конфиг AmneziaWG (`.conf`
  текстом или файлом). Подписки: base64-список ссылок по URL — то же обновление по расписанию, что у подписки
  TrustTunnel (mitt-sub.sh). Секреты (UUID, пароли, ключи) — в `secrets.json`, как у TrustTunnel.
- Запасной сервер, «самый быстрый», тест скорости, статистика и сторож туннеля переходят с «единственного профиля»
  на «каждый профиль»: `tunnel_tick` обходит все профили; состояние каждого — `$STATE/tun/<id>/…`.
- Профиль протокола, чей модуль не установлен или недоступен, сохраняется в настройках, но помечен «модуль недоступен»;
  его правила действуют по политике отказа (`block`/`direct`).

### 3. Модули

- Модуль = подписанный тем же ключом релиза tar (`mi-lumruri-mod-<name>-<ver>-arm64.tar` + `manifest.json` +
  подпись), публикуется ассетами GitHub-релиза. Каталог модулей — `modules.json` в релизе (имя, версия, размер в
  распакованном виде, sha256, требуемая версия пакета, какие протоколы даёт).
- Первые модули: **sing-box** (официальная сборка linux-arm64 с проверкой sha256 при сборке в CI; версия
  закреплена) и **amneziawg** (amneziawg-go + `awg`, собираются в CI под aarch64-musl).
- Установка: роутер скачивает модуль (через VPN, если туннель есть, иначе напрямую — как обновление), проверяет
  подпись и sha, распаковывает в `<накопитель>/mi-lumruri/modules/<name>/<ver>/`, переключает `current` (файл с
  версией, без симлинков — FAT). Запись о модуле (где лежит, версия) — в `$ETC/modules.json` в `/data`.
- Запуск: бинарник модуля копируется в RAM (`/tmp`) один раз на модуль (не на профиль), как остальные движки (FAT
  без exec-бита, флешка может отвалиться посреди работы). Перед копированием сверяется sha256.
- Память: у BE7000 1 ГБ RAM. Перед запуском профиля модуля проверяется свободная RAM (запас на процесс ~40 МБ +
  резерв прошивки); не хватает — профиль не стартует, состояние «мало памяти» в панели. Отдельного жёсткого лимита
  числа модульных профилей нет, кроме 15 туннелей.
- Каталог `modules.json` и сами модули выпускаются в каждом релизе пакета (модуль собран и закреплён под эту версию
  пакета). Обновление пакета обновляет и установленные модули из того же релиза; откат пакета откатывает модули к
  версии предыдущего релиза (она остаётся на накопителе, пока не удалена).
- Где можно ставить: `/data` (если хватает с резервом, как в install.sh) или любой смонтированный накопитель с
  записью и достаточным местом. Панель показывает варианты и блокирует кнопку, если места нет.
- Удаление модуля: только если ни один профиль его не использует (иначе панель предлагает сначала удалить/сменить
  профили). Обновление модуля: вместе с обновлением пакета, если в каталоге новая версия; откат — к предыдущей версии
  на том же накопителе.

### 4. Накопители и слежение за флешкой

- Обнаружение: разбор `/proc/mounts` — точки под `/mnt/` и `/extdisks/` с блочным устройством `/dev/sd*`;
  `df` для размера/свободного; метка/модель — из `/sys/block/sdX/device/{vendor,model}`, если есть. Rust:
  `mi-tt-ctl storage` (JSON), API `GET /storage`.
- Модуль привязан к накопителю по UUID файловой системы (`blkid`, если есть в стоке; иначе по метке тома + размеру),
  а не по пути монтирования — `/mnt/usb-XXXX` может смениться.
- Тик службы (как `tunnel_tick`): если модуль нужен (есть профиль, который использует его) и накопитель пропал или
  файлы модуля не читаются — состояние `missing`, движки профилей уже работают из RAM и продолжают работать до
  перезапуска; уведомление «флешка с модулем X недоступна; профили … работают до перезагрузки» (одно, без повторов).
  Если процесс модуля перезапускается/роутер перезагружен, а флешки нет — профили стоят, правила — по политике,
  уведомление. Флешка вернулась — проверка sha, запуск, уведомление о восстановлении.
- Панель: баннер на «Обзоре» и статус в «Модулях»/«Сервере».

### 5. Панель

- Новый пункт меню **«Модули»** (на телефоне — в «Ещё»). Блоки: «Накопители» (что подключено, свободно/всего),
  «Доступные модули» (описание протоколов, размер, выбор накопителя, «Установить»), «Установленные» (версия, где
  лежат, состояние, «Обновить»/«Удалить»).
- «Сервер»: список серверов вместо одного; «Добавить сервер» → выбор протокола (протоколы без модуля — неактивны со
  ссылкой «Установить модуль»), вставка ссылки/конфига или подписки.
- «Сайты»/«Устройства»: в правиле выбор сервера (сейчас подразумевается единственный). Если сервер один — выбор скрыт,
  интерфейс как сейчас.
- i18n ru/en/zh, руководство на трёх языках.

## Проверка

Лаборатория (qemu-user): тесты плана меток/правил на несколько туннелей, конфликт `0xf0`, установка модуля на
имитацию флешки (FAT-подобный каталог без exec), пропажа/возврат накопителя, уведомления. e2e панели для «Модулей» и
нескольких серверов. На роутере пользователя — по выпускам.
