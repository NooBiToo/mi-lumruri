# Установка на Xiaomi BE7000

**Русский** · [English](guide.en.md) · [简体中文](guide.zh-CN.md)

Инструкция для Mi Lumruri версии 0.3.3. Внутренние имена остались прежними: файлы пакета называются `mi-trusttunnel-*.tar`, на роутере пакет живёт в `/data/mi-trusttunnel` и `/tmp/mi-trusttunnel`.

Понадобятся BE7000 (RC06) с прошивкой 1.1.38, действующий root-доступ по SSH из домашней сети, установочный TAR и параметры вашего сервера TrustTunnel. Штатная релизная прошивка обычно поставляется с выключенным SSH.

## Доступ по SSH перед установкой

На штатной прошивке SSH обычно выключен. Для получения SSH-доступа на роутерах Xiaomi существует сторонняя утилита XMiR-Patcher. В её README отсутствует подтверждение совместимости именно с BE7000 (RC06) на прошивке 1.1.38. [Проект и документация XMiR-Patcher](https://github.com/openwrt-xiaomi/xmir-patcher)

Когда SSH включён, проверьте вход с компьютера в домашней сети. Подставьте LAN-адрес своего роутера:

```sh
ssh root@192.168.31.1 id -u
```

Если ответ `no matching host key type found. Their offer: ssh-rsa`, роутер предлагает старый ключ, который новый OpenSSH отключил. `install.py` разрешает его сам, а для ручных команд добавьте в `~/.ssh/config` (на Windows — `%USERPROFILE%\.ssh\config`):

```
Host 192.168.31.1
  User root
  HostKeyAlgorithms +ssh-rsa
  PubkeyAcceptedAlgorithms +ssh-rsa
```

Ответ `0` означает, что вход с правами root работает и можно запускать установщик. При `Connection refused` проверьте адрес и доступность службы SSH. При `Permission denied` SSH уже отвечает — проверьте ключ или пароль пользователя `root`.

## Быстрая установка с компьютера

Скачайте из [последнего релиза](https://github.com/NooBiToo/mi-lumruri/releases/latest) файлы `mi-trusttunnel-*.tar`, `SHA256SUMS` и `install.py` в одну папку (или распакуйте ZIP из GitHub Actions) и откройте терминал в папке с `install.py`, TAR и `SHA256SUMS`. Оставьте исходные имена файлов. На Windows выполните:

```powershell
python install.py 192.168.31.1
```

На Linux и macOS используйте `python3 install.py 192.168.31.1`. Подставьте свой LAN-адрес. Понадобятся Python 3.8+ и клиент OpenSSH. Скрипт проверит архив, передаст его по SSH и при первой установке попросит придумать пароль панели (не короче 12 символов). Сверьте выведенный отпечаток сертификата с браузером. При обновлении используется тот же способ, действующие данные входа сохраняются.

Из каталога исходников команда также работает: если пакета рядом нет, скрипт скачает последнюю успешную сборку из `main` через авторизованный GitHub CLI (`gh auth login`). Чтобы взять уже скачанный TAR, передайте `--package путь/к/файлу.tar`, рядом должен лежать его `SHA256SUMS`.

Дальше переходите к разделу [«Настройте в панели»](#3-настройте-в-панели). Ниже приведён ручной способ установки.

### Установка прямо на роутере

Сценарий [`tools/device/install-from-github.sh`](../tools/device/install-from-github.sh) скачивает пакет релиза v0.3.3 с GitHub прямо на роутер, сверяет его SHA-256 и запускает установщик. При первой установке он попросит пароль панели, в конце выведет отпечаток сертификата. Роутеру нужен доступ к `github.com`. Скопируйте сценарий на роутер и запустите в SSH-сессии:

```sh
scp -O tools/device/install-from-github.sh root@192.168.31.1:/tmp/
ssh -t root@192.168.31.1 sh /tmp/install-from-github.sh
```

### Если не хватает места в `/data`

Раздел `/data` на BE7000 небольшой: около 20,6 МБ, из них около 9 МБ занимает штатная прошивка. Установленный релиз занимает около 4,5 МБ. Установщик хочет место под новый релиз и 2 МиБ резерва для прошивки (всего около 6,5 МБ). Прежний релиз при обновлении остаётся для отката.

Если места не хватает, установщик действует так:

1. Удаляет старые релизы, кроме текущего, и пишет «место на /data: удалён старый релиз …».
2. Если места хватает только впритык (релиз и 512 КиБ, около 5 МБ), ставит новую версию, а прежний релиз удаляет после установки. Он предупреждает: «на /data мало места: после установки прежний релиз будет удалён, откат на него будет недоступен». Настройки сохраняются.
3. Если меньше и этого, останавливается с сообщением «на /data свободно … байт, нужно не меньше …; храните релизы на USB». Ничего не меняется.

Чтобы откат оставался доступен или если установщик остановился, релизы можно хранить на USB-накопителе. Настройки, ключи и автозапуск останутся в `/data`.

Подключите накопитель и узнайте, куда роутер его смонтировал:

```sh
ssh root@192.168.31.1 "grep /mnt/usb /proc/mounts"
```

Передайте установщику каталог на этом накопителе:

```powershell
python install.py 192.168.31.1 --store /mnt/usb-XXXX/mi-trusttunnel
```

При ручной установке то же делает `sh install.sh install --store=/mnt/usb-XXXX/mi-trusttunnel`. Выбор запоминается: следующие обновления ставятся без `--store`.

Что важно знать о работе с накопителем:

- **Накопитель нужен при загрузке роутера и при обновлении.** После старта программы работают из RAM. Если накопитель отключится на ходу, служба продолжит работать, и правила после перезапуска firewall восстановятся.
- **Без накопителя при загрузке служба не запустится.** Загрузчик ждёт его до 5 минут. Всё это время, а если накопитель так и не появится — до следующей загрузки с ним, правила не действуют: устройства выходят в интернет напрямую, панель недоступна.
- **При переносе с `/data` на накопитель откат на прежний релиз недоступен**, пока не установлена следующая версия.

## 1. Подготовьте пакет и проверьте роутер

Скачайте пакет из [релиза](https://github.com/NooBiToo/mi-lumruri/releases/latest) или из успешной сборки GitHub Actions либо соберите его на компьютере. Сверьте SHA-256 установочного TAR со сводкой сборки. Для команд ниже переименуйте проверенный TAR в `mitt-install.tar`. [Где скачать или как собрать пакет](build.md)

Откройте терминал на компьютере. В примерах адрес роутера — `192.168.31.1`. Подставьте свой LAN-адрес во все команды и в адрес панели.

```sh
ssh root@192.168.31.1 "df -k /data /tmp"
```

Установочный TAR весит около 4,6 МБ. Установленный релиз занимает около 4,5 МБ во внутренней памяти, распакованные программы — около 12,1 МБ в RAM. Установщик дополнительно требует 2 МиБ свободного места в `/data` и 16 МиБ в `/tmp`. При обновлении прежний релиз остаётся для отката, поэтому в `/data` нужно место ещё под один релиз; если его нет, см. [«Если не хватает места в `/data`»](#если-не-хватает-места-в-data). При копировании и распаковке пакета в `/tmp` также лежат сам архив и его содержимое. Для подробной диагностики можно выполнить [проверку совместимости в режиме чтения](../tools/device/preflight.sh).

## 2. Установите по SSH

На компьютере откройте каталог с готовым TAR и выполните:

```sh
scp -O mitt-install.tar root@192.168.31.1:/tmp/mitt-install.tar
ssh root@192.168.31.1
```

В SSH-сессии на роутере выполните блок целиком. Ключ `-O` в предыдущей команде включает протокол SCP, который понимает штатный Dropbear.

```sh
stage=$(mktemp -d /tmp/mitt-install.XXXXXX) &&
  tar xf /tmp/mitt-install.tar -C "$stage" &&
  cd "$stage/mi-trusttunnel" &&
  sh install.sh
```

После успешной установки настройте вход:

```sh
sh /data/mi-trusttunnel/mitt-boot.sh auth init
openssl x509 -in /data/mi-trusttunnel/etc/tls/cert.pem -noout -fingerprint -sha256
```

Задайте пароль панели — не короче 12 символов. Откройте **`https://192.168.31.1:8443/`** из домашней сети. При первом входе сверьте SHA-256 сертификата в браузере с отпечатком из SSH-сессии.

### Второй фактор (TOTP)

По умолчанию в панель входят только паролем. Чтобы включить одноразовые коды из приложения, выполните на роутере:

```sh
sh /data/mi-trusttunnel/mitt-boot.sh auth reset-totp
sh /data/mi-trusttunnel/mitt-boot.sh auth confirm
```

Первая команда покажет QR-код — отсканируйте его приложением-аутентификатором — и выдаст одноразовые коды восстановления. Сохраните их офлайн. Вторая попросит код из приложения. Пока код не подтверждён, вход в панель закрыт.

## 3. Настройте в панели

В меню панели восемь экранов: **«Обзор»**, **«Сайты»**, **«Устройства»**, **«Сервер»**, **«Zapret»**, **«Свои DNS-записи»**, **«Диагностика»** и **«Дополнительно»**. На телефоне в нижней панели только «Обзор», «Сайты», «Устройства», «Сервер» и «Ещё»; Zapret, свои DNS-записи и диагностика открываются из «Ещё».

Изменения на экранах сохраняются сами, отдельной кнопки «Применить» нет. Кнопка **«Сохранить»** есть только на экране «Сервер». Вверху видно, подключён ли VPN, и как идёт сохранение: «Сохраняю…», «Применяю на роутере», «Сохранено». Роутер применяет настройки сам за несколько секунд. Там же переключатель **VPN** и кнопка «Выйти».

Для первой настройки достаточно трёх шагов:

1. **«Сервер»** — вставьте ссылку на сервер или конфигурацию клиента и нажмите «Сохранить».
2. **«Сайты»** — отметьте сервисы, которые открывать через VPN.
3. Откройте выбранный сайт с любого устройства дома. На **«Обзоре»** должно быть видно, что VPN подключён.

### Сервер

Данные для подключения выдаёт сервер TrustTunnel:

```sh
trusttunnel_endpoint vpn.toml hosts.toml -c <имя пользователя> -a <IP:порт>
```

Команда печатает ссылку `tt://?…`. С ключом `--format toml` она выдаёт файл конфигурации клиента (`client.toml`). Вставьте ссылку или содержимое файла в поле карточки **«Быстрая настройка»** (позже она называется «Сменить сервер») и нажмите **«Распознать»**. Панель покажет, что распознано, и заполнит поля «Данные сервера». Проверьте их и нажмите **«Сохранить»**. Пароль только записывается: сохранённое значение панель не показывает. Чтобы сменить сервер, вставьте новую ссылку.

Поля можно заполнить и вручную. HTTP/3, маскировка, сертификат, профиль TLS и client_random спрятаны под **«Дополнительные параметры»**; обычно они приходят в ссылке.

| Поле | Что указать |
| --- | --- |
| Адрес сервера | IP-адрес или доменное имя сервера. Домен клиент TrustTunnel разрешает через DNS роутера. После удачного подключения роутер запоминает IP сервера и при следующем запуске передаёт его клиенту запасным: если DNS в этот момент не отвечает, клиент подключится по IP |
| Порт | Порт из `listen_address` в `vpn.toml` (обычно 443) |
| Имя сервера | `hostname` из `[[main_hosts]]` в `hosts.toml`. Если сертификат выпущен на IP-адрес, оставьте пустым |
| Логин и пароль | `username` и `password` из `[[client]]` в `credentials.toml` |
| HTTP/3 | Включайте, только если сервер принимает HTTP/3 и UDP до него не блокируется. Иначе используется HTTP/2 |
| Маскировка от блокировок (anti-DPI) | Параметр `anti_dpi` клиента TrustTunnel. Помогает, если провайдер мешает подключению к серверу |
| Сертификат сервера | Только для самоподписанного сертификата: содержимое файла из `cert_chain_path` (PEM). Для сертификата публичного центра оставьте пустым |
| Профиль TLS | Параметр `tls_profile` клиента TrustTunnel: под какой браузер или приложение маскируется подключение — Chrome (по умолчанию), Chrome Canary, Safari, Firefox, OkHttp (Android), OpenSSL или «Без маскировки (BoringSSL)». Приходит в ссылке, если на сервере выбран не Chrome |
| Префикс или ключ client_random | Только если сервер пускает подключения по правилу `client_random` в `rules.toml`: префикс (`client_random_prefix`) или ключ (`client_random_auth_key`). Приходит в ссылке и в `client.toml`; задаётся что-то одно |

Переключатель **«Если сервер недоступен, сайты из списка»**: «Не открывать» (рекомендуется) — сайты ждут, пока VPN снова заработает, и не уходят в обход; «Открывать напрямую» — сайты открываются через провайдера, если смогут.

В пакете клиент TrustTunnel v1.3.0, он работает с сервером TrustTunnel 1.3.1. Поддерживается один сервер TrustTunnel.

### Сайты

В карточке **«Что открывать через VPN»** выберите режим:

- **«Только выбранные»** (рекомендуется). Через VPN идут отмеченные сервисы и ваши сайты, остальное — как обычно.
- **«Всё через VPN»**. Весь интернет идёт через VPN, кроме сайтов из «Не пускать через VPN» и сайтов с обходом блокировок.

**«Сервисы»** — плитки готовых списков: YouTube, Instagram и Facebook, Discord, Telegram, ChatGPT и Google AI, TikTok, X и другие. Сервисы разбиты на группы, есть поиск. На каждой плитке три положения: **VPN** — через VPN, **Zapret** — напрямую с обходом блокировок, **Выкл** — как остальные сайты. «Всё заблокированное в России» — большой общий список; его хватает, если не знаете, что выбрать. У сервисов с собственными сетями (Telegram, Discord, Meta и другие) их IP-подсети включаются вместе с сервисом. Группа «Хостинги и CDN» включает целые сети хостингов, она нужна только специалистам.

**«Списки сайтов»** — когда обновлялись готовые списки, кнопка «Обновить» и частота проверки, см. [«Списки сайтов»](#списки-сайтов).

Свои списки доменов — по одному адресу, поддомены входят автоматически:

- **«Свои сайты через VPN»** — сайты, которых нет среди сервисов. Есть только в режиме «Только выбранные».
- **«Сайты с обходом блокировок»** — открываются напрямую, без VPN, с Zapret. Работают и при выключенном VPN.
- **«Не пускать через VPN»** — сайты, которые всегда открываются напрямую, например банки и госуслуги.

**«Остальные сайты»** (в режиме «Всё через VPN» — «Сайты, которые не идут через VPN»): «Напрямую» или «С обходом блокировок (Zapret)». Второй вариант помогает, когда YouTube или Discord без VPN тормозят или не открываются, — см. [«Обход блокировок (Zapret)»](#обход-блокировок-zapret). Способ обхода настраивается на странице «Zapret».

### Устройства

- **«Все устройства»** (рекомендуется) — настройки сайтов действуют для всей домашней сети, новые устройства подключаются сами.
- **«Только выбранные»** — например, только телевизор и ноутбук. Остальные устройства открывают все сайты напрямую. Нужные устройства отмечаются переключателем «Через VPN».

Список строится по подключённым устройствам (арендам DHCP): имя, MAC, IP-адрес и в сети ли устройство; при большом списке есть поиск. В режиме «Только выбранные» кнопка-карандаш **«Переименовать»** задаёт понятное имя — оно нужно только вам. Переименованное устройство отмечается само.

### Обзор

Пока сервер не настроен, на «Обзоре» карточка «Подключите сервер» с кнопкой «Настроить сервер».

Дальше главное — схема **«Маршруты»**: устройства → роутер → маршруты (через VPN, с обходом блокировок, напрямую) с сервисами на каждом. По действующим маршрутам бегут точки, выключенные нарисованы пунктиром; состояние VPN — индикатор на роутере. Ссылка «Изменить» ведёт на «Сайты». Карточка над схемой появляется, только когда что-то не так, и объясняет, что делать.

Переключатель **VPN** вверху панели выключает VPN: весь трафик идёт напрямую, а выбор сайтов и устройств сохраняется и заработает, когда VPN снова включат. Пока VPN выключен, сайты с обходом блокировок по-прежнему открываются с Zapret. Если же Zapret включён только для всех остальных сайтов, он выключается вместе с VPN.

Если роутер не смог применить последние настройки, вверху написано «Настройки не применены» и коротко — почему. Роутер тогда работает по прежним настройкам, а если не прошло само применение правил — держит защиту: сайты из списка VPN не откроются, пока настройки не применятся. Обычно так бывает, когда туннель ещё не поднялся: роутер сам повторяет применение раз в минуту, как только туннель готов.

За туннелем присматривает сторож. Раз в минуту, пока клиент TrustTunnel пишет «подключён», роутер делает короткий запрос через туннель. Если три запроса подряд не прошли, роутер перезапускает клиент, но не чаще раза в 5 минут. Пока клиент сам переподключается к серверу, сторож не вмешивается.

Внизу — когда обновлялись списки сайтов и ссылка **«Настроить»** на экран «Сайты», где ими управляют, см. [«Списки сайтов»](#списки-сайтов).

### Свои DNS-записи

Отдельная страница меню (на телефоне — в «Ещё»). Введите домен и IP-адрес в домашней сети и нажмите «Добавить»: домен вместе со всеми поддоменами будет отвечать этим адресом, например для сервера с Traefik. Записи сохраняются сами. Подробнее — в [«DNS»](#dns).

### Диагностика

Отдельная страница меню (на телефоне — в «Ещё»). Кнопка **«Проверить»** запускает проверку на самом роутере, она занимает до 20 секунд и ничего не меняет. Проверяется:

- служба роутера и клиент TrustTunnel — подключён ли он к серверу и с какой задержкой;
- выход в интернет через туннель — роутер спрашивает свой внешний адрес у Cloudflare (1.1.1.1) через туннель и напрямую, адреса должны различаться;
- маршрут в туннель, сортировка трафика устройств и наборы адресов;
- DNS роутера и подключённые настройки dnsmasq;
- защищённый DNS для остальных сайтов и шифрованный DNS через VPN, если они включены;
- обход блокировок (nfqws2);
- стабильность программ: падали ли клиент TrustTunnel, nfqws2 и DNS-прокси за последние 10 минут. Три перезапуска и больше — «перезапускаются по кругу».

Проверки, которые сейчас не нужны (например, VPN выключен), перечислены строкой «Не используется».

**«Проверить сайт»** показывает, каким путём роутер отправляет сайт — через VPN, напрямую с обходом блокировок или напрямую, — и отвечает ли сайт по этому пути. Сайты с обходом блокировок проверяются с роутера напрямую: Zapret обрабатывает трафик устройств, а не самого роутера. Устройство не учитывается: правила «только для выбранных устройств» показываются как для всех.

**«Журналы»** — последние записи службы, клиента TrustTunnel и Zapret на момент проверки; паролей в них нет. **«Скопировать отчёт»** кладёт итоги и журналы в буфер обмена — удобно приложить к сообщению о проблеме. **«Перезапустить службу»** заново запускает VPN и обход блокировок и применяет настройки; связь прервётся на несколько секунд.

### Дополнительно

Обычно здесь ничего менять не нужно. Изменения сохраняются сами. На телефоне вверху этого экрана — ссылки на «Zapret», «Свои DNS-записи» и «Диагностику».

- **«Блокировка рекламы»** — для всех устройств дома, через DNS роутера, см. [«Блокировка рекламы»](#блокировка-рекламы).
- **«DNS для сайтов через VPN»** — сервер и шифрование, см. [«DNS»](#dns) и [«Защищённый DNS (DoH/DoT)»](#защищённый-dns-dohdot).
- **«Защищённый DNS для остальных сайтов»** — выключен, DoH или DoT, см. [«Защищённый DNS (DoH/DoT)»](#защищённый-dns-dohdot).
- **«Вход в панель»** — включён ли второй фактор. Включается по SSH, см. [«Второй фактор (TOTP)»](#второй-фактор-totp).

### Zapret

Отдельная страница меню (на телефоне — в «Ещё»). Вверху — работает ли обход блокировок и что он обрабатывает, кнопка «Что обходить» ведёт на «Сайты». Ниже — способ обхода **«Для всех сайтов»** и **«Для YouTube»**: «Автоматически» или один из готовых способов вручную; кнопка «Вернуть автоматический». Затем **«Подобрать способ»** и **«Автопроверка способа»** — см. [«Обход блокировок (Zapret)»](#обход-блокировок-zapret).

### Если настройки изменены вручную

Панель показывает простые настройки, только если конфигурация на роутере имеет её вид. После правки через CLI (`mi-tt-ctl`) или если настройки остались от прежней версии панели, появится сообщение «Настройки изменены вручную». Пока вы ничего не меняете, роутер работает по ним. Кнопка **«Привести к простому виду»** заменяет их настройками панели.

Если сохранённые настройки не проходят проверку, панель всё равно их загружает и предлагает ту же кнопку; раздел, к которому есть замечания (например, Zapret), заменяется значениями по умолчанию. Если настройки не удаётся даже разобрать, панель пишет «Настройки на роутере не читаются» и собирает простые настройки с нуля — сервер VPN тогда нужно вставить заново. Раздел Zapret от версии 0.2.0 (`multisplit`, `pos`, `tcp_ports`) читается как «Автоматически».

## Списки сайтов

Списки сервисов взяты из проекта [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains). Снимок списков входит в пакет, поэтому всё работает сразу после установки, даже без интернета.

Роутер сам проверяет обновления на `raw.githubusercontent.com` — по умолчанию раз в сутки. Управляют списками в карточке **«Списки сайтов»** на экране «Сайты»: когда списки обновлялись и чем закончилась последняя проверка, кнопка **«Обновить»** (проверяет сразу, вместе со списком блокировки рекламы) и частота проверки — каждые 6 часов, раз в сутки, раз в неделю или только вручную. Каждый загруженный файл проверяется: ответ, не похожий на список, или список, в котором меньше половины прежних записей, не применяется, остаётся прежний. Новые версии хранятся в `/data/mi-trusttunnel/lists` и применяются сразу. Если связи нет, следующая попытка — через час. Если `/data` переполнен или недоступен для записи, обновления не сохраняются, ошибка видна на «Обзоре» и в карточке «Списки сайтов», а следующая попытка — тоже через час. При частоте «Вручную» роутер сам не проверяет, только по кнопке «Обновить».

После установки новой версии пакета действуют списки из её снимка, пока следующая проверка не загрузит свежие.

## Обход блокировок (Zapret)

Zapret (nfqws2 из [zapret2](https://github.com/bol-van/zapret2)) меняет первые пакеты соединения так, чтобы оборудование провайдера не распознало сайт. Он работает без VPN и действует только на сайты, которые идут напрямую. Сайты из списка VPN в него не попадают.

**Работает сразу.** По умолчанию способ обхода — «Автоматически (рекомендуется)». Для каждого сайта nfqws2 начинает с первой стратегии и переходит к следующей, если соединения с сайтом трижды срываются. Наборы стратегий взяты из [Zapret-Manager](https://github.com/StressOzz/Zapret-Manager): общий для сайтов по HTTPS, отдельный для YouTube, для Discord (включая голос по UDP) и для YouTube по QUIC.

**«Подобрать способ»** (страница «Zapret», когда обход блокировок используется и настройки сохранены). Роутер проверяет стратегии в стороне, не мешая сети: отдельный nfqws2 на своей очереди, проверочные запросы `curl` с выделенных портов. Устройства дома в это время работают по прежней настройке. Цели — YouTube, Discord и набор хостингов и CDN. Сначала проверка без Zapret, затем каждая стратегия общего набора. Если YouTube без Zapret не открылся, отдельно проверяются стратегии YouTube. Сайт считается открытым, если сервер ответил (кроме кода 451) и ответ не оборвался. Сайты Discord во время подбора, как и в работе, обрабатывает постоянный профиль Discord, поэтому они не влияют на выбор стратегии. Подбор занимает несколько минут, прогресс виден в панели. Если Zapret сейчас не действует (VPN выключен или все сайты всех устройств идут через VPN без исключений), кнопки нет, а вместо неё — объяснение.

Лучшая стратегия применяется, только если она открыла больше сайтов, чем без Zapret. После применения она проверяется ещё раз; если стало хуже, возвращается прежний способ. Панель показывает итог, например «Открылось 47 из 54, без обхода — 12» и «Лучший способ применён.» Если лучше не нашлось, способ не меняется, а в панели — «Способа лучше, чем без обхода, не нашлось — оставлен прежний.» Если лучше нашёлся только способ для YouTube, итог показывает цифры проверки YouTube. Вернуть автоматический режим можно кнопкой **«Вернуть автоматический»** на странице «Zapret». Если подбор прервали (остановка службы, перезагрузка), прежний способ восстанавливается.

**«Автопроверка способа»** (выключена, раз в сутки или раз в неделю) повторяет тот же подбор по расписанию, не раньше чем через 10 минут после загрузки роутера. Если действующий способ перестал помогать — находит новый; если новый хуже — оставляет прежний. Время последней автопроверки хранится в `/data`, поэтому перезагрузка расписание не сбивает.

Эффект зависит от провайдера: где фильтрации нет, Zapret ничего не меняет, а где она устроена иначе, может не помочь ни одна стратегия.

## Защищённый DNS (DoH/DoT)

Сайты через VPN роутер и так разрешает внутри туннеля. Для остальных сайтов (в том числе с обходом блокировок) вопросы по умолчанию идут к DNS провайдера открыто — провайдер может подменить ответ, и тогда не поможет даже Zapret. Переключатель **«Защищённый DNS для остальных сайтов»** в «Дополнительно» (Выключен, DoH, DoT) отправляет их по шифрованному каналу:

- **DoH** (DNS-over-HTTPS, порт 443) — рекомендуется: выглядит как обычный HTTPS. Серверы: Cloudflare, Google, AdGuard DNS, NextDNS (нужен ID профиля — 6 символов из личного кабинета) или свой сервер.
- **DoT** (DNS-over-TLS, порт 853) — провайдеры в России часто блокируют этот порт целиком. Здесь доступен и Quad9 (его DoH работает только по HTTP/2, которого в пакете нет).

Для своего сервера укажите ссылку DoH (`https://dns.example.com/dns-query`) или имя сервера DoT (`dns.example.com`) и его IP-адреса — до 4 через запятую: роутер подключается к серверу по IP, без DNS.

Работает это через программу `mi-tt-dns` на роутере: dnsmasq отправляет ей вопросы (`server=127.0.0.1#5453`, `no-resolv`), а она — выбранному серверу в постоянных TLS-соединениях, подключаясь сразу по IP. У готовых серверов (кроме NextDNS) записаны и адреса IPv6 — запасной путь: они используются, только если не отвечает ни один адрес IPv4, поэтому сеть без IPv6 ничего не теряет. Домены сайтов через VPN и свои DNS-записи обрабатываются как раньше. TLS — rustls с криптографией RustCrypto, корневые сертификаты Mozilla (webpki-roots).

Если сервер недоступен (блокировка, нет связи или после загрузки часы роутера ещё не выставлены и сертификат не проходит проверку), вопрос временно уходит к DNS провайдера — иначе пропал бы весь интернет. В «Дополнительно» и в «Диагностике» видно, сколько ответов пришло через защищённый сервер, а сколько — через провайдера, и последняя ошибка.

**Шифрование DNS через VPN.** Вопросы о сайтах через VPN и так идут внутри туннеля, провайдер их не видит; открытым остаётся только участок от VPN-сервера до DNS-сервера. Переключатель **«Шифрование»** в блоке «DNS для сайтов через VPN» (Обычный, DoH, DoT) шифрует и его: второй экземпляр `mi-tt-dns` (порт 5454) привязывает свои соединения к интерфейсу туннеля `mitt0`, мимо туннеля они уйти не могут. Запасного пути у него нет: если туннель не работает, вопросы не уходят к провайдеру, и сайты из списка ждут, пока VPN снова заработает. Обычно шифрование не нужно: вопросы и так идут внутри туннеля. Доступно для Cloudflare, Google и AdGuard; у Quad9 — только DoT; для NextDNS и своего адреса — только обычный режим (имя сервера для сертификата неизвестно). Под переключателем видно, сколько шифрованных ответов пришло через туннель или почему сервер не отвечает.

## Блокировка рекламы

Работает через DNS роутера: на домены из списка рекламы и трекеров dnsmasq отвечает «такого домена нет» (NXDOMAIN), запрос наружу не уходит. Действует на все устройства, которые получают DNS от роутера; браузер со своим «Безопасным DNS» (DoH) её обходит.

Список выбирается в «Дополнительно»: **HaGeZi Light** (по умолчанию, около 90 тыс. доменов — реклама и трекеры, почти не мешает сайтам), **HaGeZi Normal** (около 200 тыс., шире, изредка может мешать отдельным сайтам) или **своя ссылка** https на список доменов или строк hosts (`0.0.0.0 домен`; `#` — комментарий), файл до 12 МиБ. Списки [HaGeZi](https://github.com/hagezi/dns-blocklists) (GPL-3.0) взяты в виде «домен вместе с поддоменами».

Роутер скачивает список сам: сразу после включения или смены списка и затем с той же частотой, что и списки сайтов; кнопка «Обновить» в карточке «Списки сайтов» на «Сайтах» обновляет и его. Если списки сайтов обновляются только вручную, список рекламы после первой загрузки тоже обновляется только по этой кнопке (или при смене списка). Если скачать не удалось, следующая попытка — через час. Скачанный список проверяется: страница HTML, пустой ответ или файл, где не разобрано больше 5 % строк, не применяются — действует прежний; единичные кривые строки пропускаются. Рабочая копия хранится в RAM, сжатая (около 0,6–1,2 МБ) — в `/data/mi-trusttunnel/adblock.list.gz`, поэтому после перезагрузки блокировка работает сразу. В «Дополнительно» видно, сколько доменов в списке и когда он обновлялся, или почему не обновился.

## DNS

Устройства продолжают получать DNS от роутера: DHCP и локальные имена работают как раньше. Для доменов из списков dnsmasq заносит адреса из ответов в наборы правил, и по ним роутер выбирает маршрут.

Домены сайтов через VPN роутер разрешает через отдельный DNS-сервер, запросы к нему идут через туннель. Сервер выбирается на экране **«Дополнительно»** в блоке «DNS для сайтов через VPN»: Cloudflare `1.1.1.1` (по умолчанию), Quad9 `9.9.9.9`, Google `8.8.8.8`, AdGuard DNS `94.140.14.14`, NextDNS `45.90.28.0` или «Свой адрес» — любой публичный IPv4-адрес. Для NextDNS привяжите IP своего VPN-сервера в кабинете NextDNS (Linked IP), иначе фильтры не применятся. Остальные домены роутер разрешает как обычно или через [защищённый DNS](#защищённый-dns-dohdot).

**Свои DNS-записи** — домен вместе со всеми поддоменами отвечает заданным IPv4- или IPv6-адресом, вопрос наружу не уходит (dnsmasq `address=/домен/адрес`). Пример: домашний сервер с Traefik на `192.168.31.10` и домен `home.example.com` — одна запись покрывает `traefik.home.example.com`, `pve.home.example.com` и остальные. Работает для устройств, которые получают DNS от роутера; запись действует, пока работает служба mi-trusttunnel. Не добавляйте такой домен в списки сайтов через VPN или Zapret: домашний сервер должен открываться напрямую.

## Тонкая настройка через CLI

Под простыми экранами работает модель правил контроллера: источник (устройство, сеть, вся LAN) × назначение (домен, подсеть, группа, категория) × действие (через TrustTunnel, напрямую, напрямую с Zapret, блокировать). Панель собирает такие правила из ответов на экранах. Правила вида «приставка → блокировать» или разные действия для разных сетей задаются только через `mi-tt-ctl` по SSH; после этого панель покажет «Настройки изменены вручную».

## Ограничения

- **Сайты определяются по DNS.** Домены из списков работают, только пока устройство спрашивает DNS у роутера. Если на устройстве или в браузере включён собственный DoH/DoT («безопасный DNS»), роутер не видит запросы, и списки доменов к такому устройству не применяются. IP-подсети сервисов работают и в этом случае.
- **Домен совпадает и с поддоменами.** Так dnsmasq заполняет наборы ipset: `example.com` захватывает и `www.example.com`.
- **Общие IP-адреса CDN.** Маршрут выбирается по IP-адресам из ответов DNS. Если другой сайт обслуживается с того же адреса CDN, он тоже пойдёт через VPN.
- **Только IPv4.** IPv6 не туннелируется. У устройств с VPN, Zapret или блокировкой IPv6 наружу закрыт.
- **Перезагрузка firewall.** Полная перезагрузка firewall (fw3) снимает все цепочки iptables. Примерно на 1–2 секунды, пока include не применит правила снова, трафик идёт напрямую. В лаборатории это окно составило 1,2 с.
- **Подбор Zapret проверен только в лаборатории без DPI.** Там без Zapret открываются все цели, и подбор ожидаемо заканчивается словами «Способа лучше, чем без обхода, не нашлось — оставлен прежний.» Как стратегии работают против оборудования конкретного провайдера, покажет только проверка на роутере.
- **Списки обновляются с GitHub.** Если `raw.githubusercontent.com` недоступен напрямую, действуют списки из пакета или последние загруженные.
- **Один сервер TrustTunnel.** У стока свободен один бит метки, поэтому поддерживается один сервер.
- **Конфликт меток.** Маршрут выбирается по биту метки `0x4000`. Если правила прошивки его используют (например, sticky-правила mwan3 при нескольких WAN), применение отклоняется без изменений.
- **Гостевые сети** в простых настройках не участвуют.

## Обновление и откат

**Из панели.** В «Дополнительно» есть блок «Обновление». Кнопка «Проверить» узнаёт последний релиз на GitHub. Если есть новее, появится кнопка «Обновить до …». Роутер сам скачивает пакет, сверяет SHA-256 с файлом `SHA256SUMS` релиза, проверяет подпись закреплённым ключом и перезапускает службу. Панель пропадает примерно на полминуты, настройки сохраняются. Если на роутере стоит своя сборка, подписанная вашим ключом, панель предложит «Перейти на релизы GitHub и обновить». Тогда роутер примет пакет с ключом релизов GitHub (`e4a271890e5643ab`) и закрепит его. Другие ключи панель не принимает.

**С компьютера.** Для обновления повторите быструю установку или скопируйте новый TAR и повторите шаг 2 до настройки входа. Существующие настройки и второй фактор сохраняются. Релизы хранятся в `/data/mi-trusttunnel/releases` (или в каталоге `--store`): текущий и предыдущий, более старые удаляются. Для нового релиза нужно около 4,5 МБ и 2 МиБ резерва. Если столько нет, установщик удаляет старые релизы, а при совсем малом запасе ставит обновление без сохранения прежнего релиза — тогда откат недоступен, см. [«Если не хватает места в `/data`»](#если-не-хватает-места-в-data).

Обновление должно быть подписано тем же ключом, что и первая установка: при первой установке роутер закрепляет открытый ключ пакета и дальше принимает только пакеты с ним. Пакеты из релизов GitHub и сборок GitHub Actions подписаны ключом CI, а пакет, собранный на своём компьютере, — вашим ключом из `.tools/keys/`. Если поставить поверх установки из релиза свою сборку или наоборот, установщик откажет и покажет оба отпечатка: «пакет подписан другим ключом: закреплён …, у пакета …». Чтобы перейти на другой ключ, повторите установку с флагом `--trust-key` и отпечатком нового ключа из этого сообщения:

```sh
python install.py 192.168.31.1 --trust-key <отпечаток>
```

На роутере то же самое — `sh install.sh install --trust-key=<отпечаток>`. Настройки, пароли и ключи сохраняются. Новый ключ закрепляется после установки, и дальше роутер принимает только пакеты с ним. Отпечаток ключа релизов GitHub указан в описании каждого релиза.

Чтобы посмотреть состояние работающей службы, выполните по SSH:

```sh
sh /data/mi-trusttunnel/mitt-boot.sh status
```

Для отката выполните **одну** команду из каталога распакованного пакета, где находится `install.sh`. Если после перезагрузки каталог исчез, снова скопируйте и распакуйте TAR. Запускать установку для отката не требуется.

```sh
sh install.sh rollback
```

Откат доступен после установки второй версии, если установщик сохранил прежний релиз. Без него команда ответит «нет предыдущего релиза для отката». Посмотреть текущий и предыдущий релиз можно командой `sh install.sh status`.

## Удаление

Из каталога распакованного пакета, где находится `install.sh`:

```sh
sh install.sh uninstall          # с сохранением настроек в /data/mi-trusttunnel/etc
sh install.sh uninstall --purge  # вместе с настройками
```

Без пакета то же самое делается вручную по SSH:

```sh
sh /data/mi-trusttunnel/mitt-boot.sh stop
uci -q delete firewall.mitt
uci commit firewall
rm -rf /tmp/mi-trusttunnel /data/mi-trusttunnel
```

Первая команда останавливает службы, снимает правила маршрутизации и убирает файл mi-trusttunnel из настроек dnsmasq. Если релизы хранились на USB-накопителе, `install.sh uninstall` удаляет их сам, а при ручном удалении удалите и каталог, переданный в `--store`.

Без `--purge` в `/data/mi-trusttunnel` остаются настройки и закреплённый ключ подписи. Пакет с другим ключом после этого ставится с флагом `--trust-key`.

## Если вход не получается

- **SSH выдаёт отказ в соединении.** Проверьте LAN-адрес и доступность SSH на текущей прошивке. Установщик запускается уже внутри SSH-сессии.
- **Установщик сообщает о нехватке места.** Он выводит требуемый и доступный объём отдельно для `/data` и `/tmp`. Проверьте оба раздела командой из шага 1. Если не хватает именно `/data`, перенесите релизы на USB-накопитель — см. [«Если не хватает места в `/data`»](#если-не-хватает-места-в-data).
- **Установщик пишет «подпись или хэши пакета не прошли проверку».** Пакет повреждён: скачайте его заново. Если же установщик пишет «пакет подписан другим ключом», это своя сборка поверх пакета из релиза или наоборот: повторите установку с `--trust-key`, см. [«Обновление и откат»](#обновление-и-откат).
- **На «Обзоре» висит «Настройки не применены».** Откройте «Диагностику» и нажмите «Проверить»: видно, какая часть не работает. Отчёт неудачного применения роутер сохраняет в `/tmp/mi-trusttunnel/run/apply.<метка>.fail.json` — его можно приложить к сообщению о проблеме вместе с отчётом диагностики.
- **Панель отклоняет код после перезагрузки.** Проверьте время командой `date -u`. Дождитесь синхронизации часов или воспользуйтесь одноразовым кодом восстановления. Уже использованный TOTP повторно не принимается.
