# Установка на Xiaomi BE7000

Понадобятся BE7000 (RC06) с прошивкой 1.1.38, действующий root-доступ по SSH из домашней сети, установочный TAR и параметры вашего сервера TrustTunnel. Штатная релизная прошивка обычно поставляется с выключенным SSH.

## Доступ по SSH перед установкой

На штатной прошивке SSH обычно выключен. Для получения SSH-доступа на роутерах Xiaomi существует сторонняя утилита XMiR-Patcher. В её README отсутствует подтверждение совместимости именно с BE7000 (RC06) на прошивке 1.1.38. [Проект и документация XMiR-Patcher](https://github.com/openwrt-xiaomi/xmir-patcher)

Когда SSH включён, проверьте вход с компьютера в домашней сети. Подставьте LAN-адрес своего роутера:

```sh
ssh root@192.168.31.1 id -u
```

Если ответ `no matching host key type found. Their offer: ssh-rsa`, роутер предлагает старый ключ, который новый OpenSSH отключил. `install.py` разрешает его сам, а для ручных команд добавьте в `~/.ssh/config` (на Windows — `%USERPROFILE%\.ssh\config`):

```
Host 192.168.31.1
  User root
  HostKeyAlgorithms +ssh-rsa
  PubkeyAcceptedAlgorithms +ssh-rsa
```

Ответ `0` означает, что вход с правами root работает и можно запускать установщик. При `Connection refused` проверьте адрес и доступность службы SSH. При `Permission denied` SSH уже отвечает — проверьте ключ или пароль пользователя `root`.

## Быстрая установка с компьютера

Распакуйте ZIP из GitHub Actions и откройте терминал в папке с `install.py`, TAR и `SHA256SUMS`. Оставьте исходные имена файлов. На Windows выполните:

```powershell
python install.py 192.168.31.1
```

На Linux и macOS используйте `python3 install.py 192.168.31.1`. Подставьте свой LAN-адрес. Понадобятся Python 3.8+ и клиент OpenSSH. Скрипт проверит архив, передаст его по SSH и при первой установке попросит придумать пароль панели (не короче 12 символов). Сверьте выведенный отпечаток сертификата с браузером. При обновлении используется тот же способ, действующие данные входа сохраняются.

Из каталога исходников команда также работает: если пакета рядом нет, скрипт скачает последнюю успешную сборку из `main` через авторизованный GitHub CLI (`gh auth login`). Чтобы взять уже скачанный TAR, передайте `--package путь/к/файлу.tar`, рядом должен лежать его `SHA256SUMS`.

Дальше переходите к разделу [«Настройте в панели»](#3-настройте-в-панели). Ниже приведён ручной способ установки.

### Если не хватает места в `/data`

Пакет занимает около 3,8 МБ, поэтому обычно места в `/data` хватает и этот раздел не нужен. Если свободно меньше примерно 6 МБ (релиз и 2 МиБ резерва), установщик останавливается с сообщением о нехватке места. Тогда релизы можно хранить на USB-накопителе, а настройки, ключи и автозапуск останутся в `/data`.

Подключите накопитель и узнайте, куда роутер его смонтировал:

```sh
ssh root@192.168.31.1 "grep /mnt/usb /proc/mounts"
```

Передайте установщику каталог на этом накопителе:

```powershell
python install.py 192.168.31.1 --store /mnt/usb-XXXX/mi-trusttunnel
```

При ручной установке то же делает `sh install.sh install --store=/mnt/usb-XXXX/mi-trusttunnel`. Выбор запоминается: следующие обновления ставятся без `--store`.

Что важно знать о работе с накопителем:

- **Накопитель нужен при загрузке роутера и при обновлении.** После старта программы работают из RAM. Если накопитель отключится на ходу, служба продолжит работать, и правила после перезапуска firewall восстановятся.
- **Без накопителя при загрузке служба не запустится.** Загрузчик ждёт его до 5 минут. Всё это время, а если накопитель так и не появится — до следующей загрузки с ним, правила не действуют: устройства выходят в интернет напрямую, панель недоступна.
- **При переносе с `/data` на накопитель откат на прежний релиз недоступен**, пока не установлена следующая версия.

## 1. Подготовьте пакет и проверьте роутер

Скачайте архив из успешной сборки GitHub Actions или соберите его на компьютере. Сверьте SHA-256 установочного TAR со сводкой сборки. Для команд ниже переименуйте проверенный TAR в `mitt-install.tar`. [Где скачать или как собрать пакет](build.md)

Откройте терминал на компьютере. В примерах адрес роутера — `192.168.31.1`. Подставьте свой LAN-адрес во все команды и в адрес панели.

```sh
ssh root@192.168.31.1 "df -k /data /tmp"
```

Установленный релиз занимает около 3,8 МБ во внутренней памяти, распакованные программы — около 10,2 МБ в RAM. Установщик дополнительно требует 2 МиБ свободного места в `/data` и 16 МиБ в `/tmp`. При обновлении прежний релиз остаётся для отката, поэтому в `/data` нужно место ещё под один релиз. При копировании и распаковке пакета в `/tmp` также лежат сам архив и его содержимое. Для подробной диагностики можно выполнить [проверку совместимости в режиме чтения](../tools/device/preflight.sh).

## 2. Установите по SSH

На компьютере откройте каталог с готовым TAR и выполните:

```sh
scp -O mitt-install.tar root@192.168.31.1:/tmp/mitt-install.tar
ssh root@192.168.31.1
```

В SSH-сессии на роутере выполните блок целиком. Ключ `-O` в предыдущей команде включает протокол SCP, который понимает штатный Dropbear.

```sh
stage=$(mktemp -d /tmp/mitt-install.XXXXXX) &&
  tar xf /tmp/mitt-install.tar -C "$stage" &&
  cd "$stage/mi-trusttunnel" &&
  sh install.sh
```

После успешной установки настройте вход:

```sh
sh /data/mi-trusttunnel/mitt-boot.sh auth init
openssl x509 -in /data/mi-trusttunnel/etc/tls/cert.pem -noout -fingerprint -sha256
```

Задайте пароль панели — не короче 12 символов. Откройте **`https://192.168.31.1:8443/`** из домашней сети. При первом входе сверьте SHA-256 сертификата в браузере с отпечатком из SSH-сессии.

### Второй фактор (TOTP)

По умолчанию в панель входят только паролем. Чтобы включить одноразовые коды из приложения, выполните на роутере:

```sh
sh /data/mi-trusttunnel/mitt-boot.sh auth reset-totp
sh /data/mi-trusttunnel/mitt-boot.sh auth confirm
```

Первая команда покажет QR-код — отсканируйте его приложением-аутентификатором — и выдаст одноразовые коды восстановления. Сохраните их офлайн. Вторая попросит код из приложения. Пока код не подтверждён, вход в панель закрыт.

## 3. Настройте в панели

В панели пять экранов: **«Состояние»**, **«Сайты»**, **«Устройства»**, **«Сервер»** и **«Дополнительно»**. Отдельной кнопки «Применить» нет: после **«Сохранить»** роутер применяет настройки сам за несколько секунд. Вверху всегда видно, подключён ли VPN.

Для первой настройки достаточно трёх шагов:

1. **«Сервер»** — вставьте ссылку на сервер или конфигурацию клиента и сохраните.
2. **«Сайты»** — отметьте сервисы, которые открывать через VPN, и сохраните.
3. Откройте выбранный сайт с любого устройства дома. На **«Состоянии»** должно быть видно, что VPN подключён.

### Сервер

Данные для подключения выдаёт сервер TrustTunnel:

```sh
trusttunnel_endpoint vpn.toml hosts.toml -c <имя пользователя> -a <IP:порт>
```

Команда печатает ссылку `tt://?…`. С ключом `--format toml` она выдаёт файл конфигурации клиента. Вставьте ссылку или содержимое файла в поле **«Вставьте ссылку на сервер»** — поля ниже заполнятся сами. Проверьте их и нажмите **«Сохранить»**. Пароль только записывается: сохранённое значение панель не показывает. Чтобы сменить сервер, вставьте новую ссылку.

Поля можно заполнить и вручную:

| Поле | Что указать |
| --- | --- |
| Адрес сервера | Публичный IP-адрес сервера. Только IP: роутер не разрешает имя сервера |
| Порт | Порт из `listen_address` в `vpn.toml` (обычно 443) |
| Имя сервера | `hostname` из `[[main_hosts]]` в `hosts.toml`. Если сертификат выпущен на IP-адрес, оставьте пустым |
| Логин и пароль | `username` и `password` из `[[client]]` в `credentials.toml` |
| HTTP/3 | Включайте, только если сервер принимает HTTP/3 и UDP до него не блокируется. Иначе используется HTTP/2 |
| Маскировка от блокировок (anti-DPI) | Параметр `anti_dpi` клиента TrustTunnel. Помогает, если провайдер мешает подключению к серверу |
| Сертификат сервера | Только для самоподписанного сертификата: содержимое файла из `cert_chain_path` (PEM). Для сертификата публичного центра оставьте пустым |

Переключатель **«Если сервер недоступен»**: «Не открывать сайты из списка» (рекомендуется) — сайты ждут, пока VPN снова заработает, и не уходят в обход; «Открывать их напрямую» — сайты открываются через провайдера, если смогут.

Поддерживается один сервер TrustTunnel.

### Сайты

Вверху выберите режим:

- **«Только выбранные сайты через VPN»** (рекомендуется). Через VPN идут отмеченные сервисы и ваши сайты, остальное — напрямую.
- **«Всё через VPN, кроме исключений»**. Весь интернет идёт через VPN, кроме сайтов из поля «Не пускать через VPN».

**«Сервисы через VPN»** — галочки по готовым спискам: YouTube, Instagram и Facebook, Discord, Telegram, ChatGPT и Google AI, TikTok, X и другие. «Всё заблокированное в России» — большой общий список; его хватает, если не знаете, что выбрать. У сервисов с собственными сетями (Telegram, Discord, Meta и другие) их IP-подсети включаются той же галочкой. Раздел «Хостинги и CDN» включает целые сети хостингов, он нужен только специалистам.

**«Свои сайты»** — домены, которых нет в списках, по одному в строке. Поддомены тоже идут через VPN. **«Не пускать через VPN»** — сайты, которые всегда открываются напрямую, например банки и госуслуги.

**«Остальные сайты»**: «Напрямую» или «Напрямую с обходом блокировок (Zapret)». Второй вариант помогает, когда YouTube или Discord без VPN тормозят или не открываются, — см. [«Обход блокировок (Zapret)»](#обход-блокировок-zapret).

### Устройства

- **«Все устройства дома»** (рекомендуется) — настройки сайтов действуют для всей домашней сети, новые устройства подключаются сами.
- **«Только выбранные»** — например, только телевизор и ноутбук. Остальные устройства открывают все сайты напрямую.

Список строится по подключённым устройствам (арендам DHCP): имя, IP-адрес и MAC. Кнопка **«Переименовать»** задаёт понятное имя — оно нужно только вам.

### Состояние

Показывает, подключён ли VPN, что и для каких устройств идёт через VPN, как открываются остальные сайты и какой сервер выбран. Кнопка **«Выключить VPN»** отправляет весь трафик напрямую, при этом выбор сайтов и устройств сохраняется; **«Включить VPN»** возвращает его.

Там же блок **«Списки сайтов»**: когда списки обновлялись и кнопка **«Обновить списки»** — см. [«Списки сайтов»](#списки-сайтов).

### Дополнительно

Обычно здесь ничего менять не нужно.

- **«Блокировать рекламу»** — для всех устройств дома: рекламные домены получают ответ NXDOMAIN, запрос наружу не уходит.
- **«DNS-сервер для сайтов через VPN»** — см. [«DNS»](#dns).
- **«Обход блокировок (Zapret)»** — текущий способ обхода и кнопка **«Вернуть автоматический»**. Кнопка **«Подобрать способ заново»** открывает блок Zapret на экране «Сайты», где запускается подбор.
- **«Вход в панель»** — включён ли второй фактор. Включается по SSH, см. [«Второй фактор (TOTP)»](#второй-фактор-totp).

### Если настройки изменены вручную

Панель показывает простые настройки, только если конфигурация на роутере имеет её вид. После правки через CLI (`mi-tt-ctl`) или если настройки остались от прежней версии панели, появится сообщение «Настройки изменены вручную». Пока вы ничего не меняете, роутер работает по ним. Кнопка **«Привести к простому виду»** заменяет их настройками панели.

## Списки сайтов

Списки сервисов взяты из проекта [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains). Снимок списков входит в пакет, поэтому всё работает сразу после установки, даже без интернета.

Раз в сутки роутер сам проверяет обновления на `raw.githubusercontent.com`. Каждый загруженный файл проверяется: ответ, не похожий на список, или список, в котором меньше половины прежних записей, не применяется, остаётся прежний. Новые версии хранятся в `/data/mi-trusttunnel/lists` и применяются сразу. Если связи нет, следующая попытка — через час. Проверить обновления сразу можно кнопкой **«Обновить списки»** на «Состоянии». Там же видно, когда списки обновлялись и удалась ли последняя проверка.

После установки новой версии пакета действуют списки из её снимка, пока следующая проверка не загрузит свежие.

## Обход блокировок (Zapret)

Zapret (nfqws2 из [zapret2](https://github.com/bol-van/zapret2)) меняет первые пакеты соединения так, чтобы оборудование провайдера не распознало сайт. Он работает без VPN и действует только на сайты, которые идут напрямую. Сайты из списка VPN в него не попадают.

**Работает сразу.** По умолчанию способ обхода — «Автоматически (рекомендуется)». Для каждого сайта nfqws2 начинает с первой стратегии и переходит к следующей, если соединения с сайтом трижды срываются. Наборы стратегий взяты из [Zapret-Manager](https://github.com/StressOzz/Zapret-Manager): общий для сайтов по HTTPS, отдельный для YouTube, для Discord (включая голос по UDP) и для YouTube по QUIC.

**«Подобрать способ»** (экран «Сайты», когда выбран Zapret и настройки сохранены). Роутер проверяет стратегии в стороне, не мешая сети: отдельный nfqws2 на своей очереди, проверочные запросы `curl` с выделенных портов. Устройства дома в это время работают по прежней настройке. Цели — YouTube, Discord и набор хостингов и CDN. Сначала проверка без Zapret, затем каждая стратегия общего набора. Если YouTube без Zapret не открылся, отдельно проверяются стратегии YouTube. Сайт считается открытым, если сервер ответил (кроме кода 451) и ответ не оборвался. Подбор занимает несколько минут, прогресс виден в панели.

Лучшая стратегия применяется, только если она открыла больше сайтов, чем без Zapret. После применения она проверяется ещё раз; если стало хуже, возвращается прежний способ. Панель показывает итог, например «Открылось 47 из 54, без обхода — 12» и «Лучший способ применён.» Если лучше не нашлось, способ не меняется, а в панели — «Способа лучше, чем без обхода, не нашлось — оставлен прежний.» Вернуть автоматический режим можно на экране «Дополнительно». Если подбор прервали (остановка службы, перезагрузка), прежний способ восстанавливается.

Эффект зависит от провайдера: где фильтрации нет, Zapret ничего не меняет, а где она устроена иначе, может не помочь ни одна стратегия.

## DNS

Устройства продолжают получать DNS от роутера: DHCP и локальные имена работают как раньше. Для доменов из списков dnsmasq заносит адреса из ответов в наборы правил, и по ним роутер выбирает маршрут.

Домены сайтов через VPN роутер разрешает через отдельный DNS-сервер, запросы к нему идут через туннель. По умолчанию это `1.1.1.1`. Сменить его можно на экране **«Дополнительно»** в поле «DNS-сервер для сайтов через VPN», допускается публичный IPv4-адрес. Остальные домены роутер разрешает как обычно.

## Тонкая настройка через CLI

Под простыми экранами работает модель правил контроллера: источник (устройство, сеть, вся LAN) × назначение (домен, подсеть, группа, категория) × действие (через TrustTunnel, напрямую, напрямую с Zapret, блокировать). Панель собирает такие правила из ответов на экранах. Правила вида «приставка → блокировать» или разные действия для разных сетей задаются только через `mi-tt-ctl` по SSH; после этого панель покажет «Настройки изменены вручную».

## Ограничения

- **Сайты определяются по DNS.** Домены из списков работают, только пока устройство спрашивает DNS у роутера. Если на устройстве или в браузере включён собственный DoH/DoT («безопасный DNS»), роутер не видит запросы, и списки доменов к такому устройству не применяются. IP-подсети сервисов работают и в этом случае.
- **Домен совпадает и с поддоменами.** Так dnsmasq заполняет наборы ipset: `example.com` захватывает и `www.example.com`.
- **Общие IP-адреса CDN.** Маршрут выбирается по IP-адресам из ответов DNS. Если другой сайт обслуживается с того же адреса CDN, он тоже пойдёт через VPN.
- **Только IPv4.** IPv6 не туннелируется. У устройств с VPN, Zapret или блокировкой IPv6 наружу закрыт.
- **Перезагрузка firewall.** Полная перезагрузка firewall (fw3) снимает все цепочки iptables. Примерно на 1–2 секунды, пока include не применит правила снова, трафик идёт напрямую. В лаборатории это окно составило 1,2 с.
- **Подбор Zapret проверен только в лаборатории без DPI.** Там без Zapret открываются все цели, и подбор ожидаемо заканчивается словами «Способа лучше, чем без обхода, не нашлось — оставлен прежний.» Как стратегии работают против оборудования конкретного провайдера, покажет только проверка на роутере.
- **Списки обновляются с GitHub.** Если `raw.githubusercontent.com` недоступен напрямую, действуют списки из пакета или последние загруженные.
- **Один сервер TrustTunnel.** У стока свободен один бит метки, поэтому поддерживается один сервер.
- **Конфликт меток.** Маршрут выбирается по биту метки `0x4000`. Если правила прошивки его используют (например, sticky-правила mwan3 при нескольких WAN), применение отклоняется без изменений.
- **Гостевые сети** в простых настройках не участвуют.

## Обновление и откат

Для обновления повторите быструю установку или скопируйте новый TAR и повторите шаг 2 до настройки входа. Существующие настройки и второй фактор сохраняются. Потребуется место ещё для одного релиза (около 3,8 МБ). Обновление должно быть подписано тем же ключом, что и первая установка.

Чтобы посмотреть состояние работающей службы, выполните по SSH:

```sh
sh /data/mi-trusttunnel/mitt-boot.sh status
```

Для отката выполните **одну** команду из каталога распакованного пакета, где находится `install.sh`. Если после перезагрузки каталог исчез, снова скопируйте и распакуйте TAR. Запускать установку для отката не требуется.

```sh
sh install.sh rollback
```

Откат доступен после установки второй версии.

## Удаление

Из каталога распакованного пакета, где находится `install.sh`:

```sh
sh install.sh uninstall          # с сохранением настроек в /data/mi-trusttunnel/etc
sh install.sh uninstall --purge  # вместе с настройками
```

Без пакета то же самое делается вручную по SSH:

```sh
sh /data/mi-trusttunnel/mitt-boot.sh stop
uci -q delete firewall.mitt
uci commit firewall
rm -rf /tmp/mi-trusttunnel /data/mi-trusttunnel
```

Первая команда останавливает службы, снимает правила маршрутизации и убирает файл mi-trusttunnel из настроек dnsmasq. Если релизы хранились на USB-накопителе, удалите и каталог, переданный в `--store`.

## Если вход не получается

- **SSH выдаёт отказ в соединении.** Проверьте LAN-адрес и доступность SSH на текущей прошивке. Установщик запускается уже внутри SSH-сессии.
- **Установщик сообщает о нехватке места.** Он выводит требуемый и доступный объём отдельно для `/data` и `/tmp`. Проверьте оба раздела командой из шага 1. Если не хватает именно `/data`, перенесите релизы на USB-накопитель — см. [«Если не хватает места в `/data`»](#если-не-хватает-места-в-data).
- **Панель отклоняет код после перезагрузки.** Проверьте время командой `date -u`. Дождитесь синхронизации часов или воспользуйтесь одноразовым кодом восстановления. Уже использованный TOTP повторно не принимается.
