# Сборка и проверка

## Сборка на GitHub

В разделе **Actions → BE7000 ARM64** откройте успешный запуск для нужного коммита. В **Artifacts** скачайте `mi-trusttunnel-be7000` и распакуйте ZIP на компьютере. Внутри лежат установочный TAR и `SHA256SUMS`. На Linux командой `sha256sum -c SHA256SUMS` можно проверить архив. В PowerShell выполните `Get-FileHash *.tar` и сравните результат с SHA-256 в сводке запуска.

Сборка запускается при отправке изменений в `main` или кнопкой **Run workflow** для этой ветки. Для подписи используется постоянный секрет Actions `BE7000_SIGNING_KEY` (закрытый ключ Ed25519 в формате PEM). При его отсутствии сборка останавливается. Установленную на роутер сборку можно обновить пакетом с тем же ключом подписи.

## Локальная сборка

Собирайте на компьютере. Для команд ниже подойдёт Ubuntu x86_64 с Bash, Node.js 22.12 или новее, npm, Python 3.12+, curl, компилятором для хоста и утилитами apt. Понадобится интернет для первой загрузки зависимостей. Команды выполняются из корня проекта.

## Установочный пакет

```sh
tools/setup-tools.sh
tools/lab/fetch-zapret.sh
tools/cargo.sh build --release --locked --target aarch64-unknown-linux-musl
(cd panel && npm ci && npm run build)
node tools/package.mjs
```

Клиент TrustTunnel для ARM64 (v1.1.12, архив закреплён по SHA-256) `tools/package.mjs` скачивает сам. Готовый TAR и JSON-отчёт с SHA-256 находятся в `out/package/`. На роутер переносится **TAR**. Для последующих обновлений сохраните закрытый ключ своей сборки из `.tools/keys/` в защищённом месте. При первом запуске сборщик создаёт его автоматически, а роутер закрепляет соответствующий открытый ключ при установке. [Инструкция для роутера](guide.md)

## Тесты

```sh
tools/cargo.sh test --locked
(cd panel && npm ci && npm test && npm run build)
```

Полный прогон на подготовленном стенде запускается командой `bash tools/check-all.sh`. Он включает HTTPS-стенд, сборку ARM64, проверку пакета и сетевые лаборатории. Проверяйте также сообщения о пропусках: без QEMU или сервера TrustTunnel (`tools/lab/fetch.sh`) часть проверок пропускается.

Лаборатории можно запустить и по отдельности в Linux (подходит WSL2) после сборки пакета: `tools/lab/run-lab-install.sh` — установка, обновление, откат и удаление на штатном BusyBox под qemu; `tools/lab/run-lab-boot.sh` — автозагрузка, служба и правила с настоящим сервером `trusttunnel_endpoint`, официальным клиентом, dnsmasq с ipset и штатными BusyBox, nginx и uhttpd прошивки под qemu. Результаты сохраняются в `out/lab/`. История этапов описана в [журнале](../VERTICAL-SLICE.md).

| Каталог | Содержимое |
| --- | --- |
| `controller/` | Rust-контроллер конфигурации и административная утилита |
| `panel/`, `stand/` | Веб-панель и локальный HTTPS-стенд |
| `package/` | Установщик, служба и начальные настройки |
| `tools/lab/` | Изолированные сетевые сценарии |
