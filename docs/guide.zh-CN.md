# 在小米 BE7000 上安装

[Русский](guide.md) · [English](guide.en.md) · **简体中文**

本说明适用于 Mi Lumruri 0.7.0 版本。安装包文件名为 `mi-lumruri-*.tar`，在路由器上安装包位于 `/data/mi-lumruri` 和 `/tmp/mi-lumruri`。0.5.0 之前项目名为 mi-trusttunnel：在旧版本之上安装 0.5.0 时，会自动把 `/data/mi-trusttunnel` 连同全部设置移动到 `/data/mi-lumruri`，并在原位置留下链接。发布版中除主安装包外还有一份名为 `mi-trusttunnel-*.tar` 的副本，供 0.4 版本面板中的更新功能查找。

你需要：固件版本为 1.1.38 的 BE7000（RC06）、可从家庭网络通过 SSH 获得的 root 权限、安装用 TAR 包，以及你的 TrustTunnel 服务器参数。官方发布的原厂固件通常默认关闭 SSH。

## 安装前开启 SSH 访问

原厂固件上 SSH 通常是关闭的。第三方工具 XMiR-Patcher 可用于在小米路由器上获取 SSH 访问权限。其 README 中没有确认它与固件 1.1.38 的 BE7000（RC06）兼容。[XMiR-Patcher 项目及文档](https://github.com/openwrt-xiaomi/xmir-patcher)

开启 SSH 后，在家庭网络中的电脑上检查能否登录。请替换为你的路由器 LAN 地址：

```sh
ssh root@192.168.31.1 id -u
```

如果返回 `no matching host key type found. Their offer: ssh-rsa`，说明路由器提供的是新版 OpenSSH 已禁用的旧密钥类型。`install.py` 会自动允许该类型；手动执行命令时，请在 `~/.ssh/config`（Windows 上为 `%USERPROFILE%\.ssh\config`）中添加：

```
Host 192.168.31.1
  User root
  HostKeyAlgorithms +ssh-rsa
  PubkeyAcceptedAlgorithms +ssh-rsa
```

返回 `0` 表示 root 登录正常，可以运行安装程序。如果出现 `Connection refused`，请检查地址以及 SSH 服务是否可用。如果出现 `Permission denied`，说明 SSH 已有响应，请检查 `root` 用户的密钥或密码。

## 从电脑快速安装

从[最新发布版本](https://github.com/NooBiToo/mi-lumruri/releases/latest)下载 `mi-lumruri-*.tar`、`SHA256SUMS` 和 `install.py` 到同一文件夹（或解压 GitHub Actions 中的 ZIP），然后在包含 `install.py`、TAR 和 `SHA256SUMS` 的文件夹中打开终端。请保留原始文件名。在 Windows 上执行：

```powershell
python install.py 192.168.31.1
```

在 Linux 和 macOS 上使用 `python3 install.py 192.168.31.1`。请替换为你的 LAN 地址。需要 Python 3.8+ 和 OpenSSH 客户端。脚本会校验压缩包，通过 SSH 传输到路由器，首次安装时会要求你设置面板密码（不少于 12 个字符）。请将输出的证书指纹与浏览器中显示的指纹进行核对。更新时使用相同方法，现有的登录信息会保留。

在源码目录中也可以运行此命令：如果旁边没有安装包，脚本会通过已登录的 GitHub CLI（`gh auth login`）下载 `main` 分支上最近一次成功的构建。若要使用已下载的 TAR，请传入 `--package 路径/到/文件.tar`，且该文件旁边须有对应的 `SHA256SUMS`。

接下来请转到[「在面板中配置」](#3-在面板中配置)一节。下面介绍手动安装方法。

### 直接在路由器上安装

脚本 [`tools/device/install-from-github.sh`](../tools/device/install-from-github.sh) 会直接在路由器上从 GitHub 下载脚本中写明地址的发布版本安装包，校验其 SHA-256 并运行安装程序。首次安装时会要求设置面板密码，最后输出证书指纹。路由器需要能访问 `github.com`。将脚本复制到路由器，并在 SSH 会话中运行：

```sh
scp -O tools/device/install-from-github.sh root@192.168.31.1:/tmp/
ssh -t root@192.168.31.1 sh /tmp/install-from-github.sh
```

### `/data` 空间不足时

BE7000 上的 `/data` 分区很小：约 20.6 MB，其中约 9 MB 被原厂固件占用。已安装的版本约占 4.5 MB。安装程序需要为新版本留出空间，并为固件保留 2 MiB 余量（合计约 6.5 MB）。更新时旧版本会保留，以便回滚。

空间不足时，安装程序按以下步骤处理：

1. 删除除当前版本以外的旧版本，并输出「/data 空间：已删除旧版本 …」（«место на /data: удалён старый релиз …»）。
2. 如果空间只够勉强容纳（版本本身加 512 KiB，约 5 MB），则安装新版本，安装完成后删除旧版本。此时会提示：「/data 空间不足：安装后将删除旧版本，无法回滚到该版本」（«на /data мало места: после установки прежний релиз будет удалён, откат на него будет недоступен»）。配置会保留。
3. 如果连这些空间都没有，则停止并提示「/data 可用 … 字节，至少需要 …；请将版本存放在 USB 上」（«на /data свободно … байт, нужно не меньше …; храните релизы на USB»）。不做任何更改。

如果希望保留回滚能力，或者安装程序已停止，可以将版本存放在 USB 存储设备上。配置、密钥和开机自启仍保留在 `/data` 中。

插入存储设备，并查看路由器将其挂载到了哪里：

```sh
ssh root@192.168.31.1 "grep /mnt/usb /proc/mounts"
```

将该存储设备上的目录传给安装程序：

```powershell
python install.py 192.168.31.1 --store /mnt/usb-XXXX/mi-lumruri
```

手动安装时，`sh install.sh install --store=/mnt/usb-XXXX/mi-lumruri` 的作用相同。该选择会被记住：之后的更新无需再加 `--store`。

使用存储设备时需要注意：

- **路由器启动和更新时需要存储设备。** 程序启动后在 RAM 中运行。如果运行中存储设备断开，服务会继续工作，防火墙重启后规则也会恢复。
- **启动时没有存储设备，服务将无法启动。** 启动程序最多等待 5 分钟。在此期间，以及如果存储设备一直未出现、直到下次带着它启动之前，规则都不生效：设备直接访问互联网，面板不可用。
- **从 `/data` 迁移到存储设备后，无法回滚到之前的版本**，直到安装下一个版本为止。

## 1. 准备安装包并检查路由器

从[发布版本](https://github.com/NooBiToo/mi-lumruri/releases/latest)或 GitHub Actions 的成功构建中下载安装包，也可以在电脑上自行构建。请将安装用 TAR 的 SHA-256 与构建摘要进行核对。为便于执行下面的命令，请将已校验的 TAR 重命名为 `mitt-install.tar`。[在哪里下载或如何构建安装包](build.md)（俄语）

在电脑上打开终端。示例中路由器地址为 `192.168.31.1`。请在所有命令和面板地址中替换为你的 LAN 地址。

```sh
ssh root@192.168.31.1 "df -k /data /tmp"
```

安装用 TAR 约 4.6 MB。已安装的版本在内部存储中约占 4.5 MB，解压后的程序在 RAM 中约占 12.2 MB。安装程序还要求 `/data` 中有 2 MiB、`/tmp` 中有 16 MiB 可用空间。更新时旧版本会保留以便回滚，因此 `/data` 中还需要再容纳一个版本的空间；如果不够，请参阅[「`/data` 空间不足时」](#data-空间不足时)。复制和解压安装包时，`/tmp` 中还会存放压缩包本身及其内容。如需详细诊断，可以运行[只读模式的兼容性检查](../tools/device/preflight.sh)。

## 2. 通过 SSH 安装

在电脑上打开存放 TAR 的目录并执行：

```sh
scp -O mitt-install.tar root@192.168.31.1:/tmp/mitt-install.tar
ssh root@192.168.31.1
```

在路由器的 SSH 会话中完整执行以下代码块。上一条命令中的 `-O` 参数启用 SCP 协议，原厂的 Dropbear 支持该协议。

```sh
stage=$(mktemp -d /tmp/mitt-install.XXXXXX) &&
  tar xf /tmp/mitt-install.tar -C "$stage" &&
  cd "$stage/mi-lumruri" &&
  sh install.sh
```

安装成功后，配置登录：

```sh
sh /data/mi-lumruri/mitt-boot.sh auth init
openssl x509 -in /data/mi-lumruri/etc/tls/cert.pem -noout -fingerprint -sha256
```

设置面板密码，不少于 12 个字符。从家庭网络中打开 **`https://192.168.31.1:8443/`**。首次登录时，请将浏览器中证书的 SHA-256 与 SSH 会话中输出的指纹进行核对。

### 第二因素（TOTP）

默认情况下仅凭密码即可登录面板。若要启用验证器应用中的一次性验证码，请在路由器上执行：

```sh
sh /data/mi-lumruri/mitt-boot.sh auth reset-totp
sh /data/mi-lumruri/mitt-boot.sh auth confirm
```

第一条命令会显示二维码（请用验证器应用扫描），并给出一次性恢复码。请离线保存这些恢复码。第二条命令会要求输入应用中的验证码。在验证码确认之前，面板无法登录。

## 3. 在面板中配置

面板菜单中有八个页面：**「概览」**、**「网站」**、**「设备」**、**「服务器」**、**「Zapret」**、**「自定义 DNS 记录」**、**「诊断」**和**「高级」**。在手机上，底部栏只有「概览」「网站」「设备」「服务器」和「更多」；Zapret、自定义 DNS 记录和诊断从「更多」中打开。

各页面上的更改会自动保存，没有单独的「应用」按钮。**「保存」**按钮只出现在「服务器」页面。顶部显示 VPN 是否已连接以及保存进度：「正在保存…」「正在路由器上应用」「已保存」。路由器会在几秒内自动应用配置。顶部还有 **VPN** 开关和「退出」按钮。

面板支持俄语、英语和简体中文。默认按浏览器语言选择界面语言。可以在「高级」和登录页面中更改，所选语言会保存在当前浏览器中。路由器返回的详细诊断信息仍为俄语。

首次配置只需三步：

1. **「服务器」**：粘贴服务器链接或客户端配置，然后点击「保存」。
2. **「网站」**：勾选需要通过 VPN 访问的服务。
3. 在家中任意设备上打开所选网站。**「概览」**中应显示 VPN 已连接。

### 服务器

连接参数由 TrustTunnel 服务器生成：

```sh
trusttunnel_endpoint vpn.toml hosts.toml -c <用户名> -a <IP:端口>
```

该命令会输出 `tt://?…` 链接。加上 `--format toml` 参数时，它会输出客户端配置文件（`client.toml`）。将链接或文件内容粘贴到 **「快速设置」**卡片的输入框中（之后该卡片会改名为「更换服务器」），然后点击 **「识别」**。面板会显示识别结果，并填写「服务器信息」中的字段。检查无误后点击 **「保存」**。密码只能写入：面板不会显示已保存的值。要更换服务器，粘贴新的链接即可。

字段也可以手动填写。HTTP/3、伪装、证书、TLS 指纹配置和 client_random 位于 **「高级参数」**下；通常它们已包含在链接中。

| 字段 | 填写内容 |
| --- | --- |
| 服务器地址 | 服务器的 IP 地址或域名。域名由 TrustTunnel 客户端通过路由器的 DNS 解析，另见[「与服务器的连接中断时」](#与服务器的连接中断时) |
| 端口 | `vpn.toml` 中 `listen_address` 的端口（通常为 443） |
| 服务器名称 | `hosts.toml` 中 `[[main_hosts]]` 的 `hostname`。如果证书是签发给 IP 地址的，请留空 |
| 用户名和密码 | `credentials.toml` 中 `[[client]]` 的 `username` 和 `password` |
| HTTP/3 | 仅当服务器接受 HTTP/3 且到服务器的 UDP 未被封锁时才启用。否则使用 HTTP/2 |
| 反封锁伪装（anti-DPI） | TrustTunnel 客户端的 `anti_dpi` 参数。在运营商干扰与服务器的连接时有帮助 |
| 服务器证书 | 仅用于自签名证书：`cert_chain_path` 指向的文件内容（PEM）。公共证书颁发机构签发的证书请留空 |
| TLS 指纹配置 | TrustTunnel 客户端的 `tls_profile` 参数：连接伪装成哪种浏览器或应用，可选 Chrome（默认）、Chrome Canary、Safari、Firefox、OkHttp（Android）、OpenSSL 或「不伪装（BoringSSL）」。如果服务器选择的不是 Chrome，该值会包含在链接中 |
| client_random 前缀或密钥 | 仅当服务器按 `rules.toml` 中的 `client_random` 规则放行连接时填写：前缀（`client_random_prefix`）或密钥（`client_random_auth_key`）。包含在链接和 `client.toml` 中；二者只填其一 |
| 订阅链接 | TrustTunnel 1.3 订阅（服务器 `vpn.toml` 中的 `[subscription]`，`tt://` 链接中的 `0x0E` 标签）。路由器通过它自动获取服务器地址、服务器名称、用户名、密码、HTTP/3、anti-DPI、证书和 client_random 前缀：按网站列表的更新计划获取，或在点击「按订阅更新」时获取。参数有变化就会应用。也可以粘贴只包含订阅的链接：保存后路由器会获取地址和密码。链接中包含用户名和密码，因此只保存在路由器上。订阅不会更改 TLS 指纹配置和 client_random 密钥 |

开关 **「服务器不可用时，列表中的网站」**：「不打开」（推荐）表示网站会等待 VPN 恢复，不会绕过 VPN 直连；「直接打开」表示网站在可行时通过运营商直接打开。

安装包内置 TrustTunnel 客户端 v1.3.0，可配合 TrustTunnel 服务器 1.3.1 使用。

#### 备用服务器

保存主服务器后，「服务器」页面上会出现 **「备用服务器」**卡片。点击「添加」，粘贴备用服务器的链接或 `client.toml`，然后点击「识别」；也可以手动填写地址、端口、服务器名称、用户名、密码和 anti-DPI。然后点击「保存」。与主服务器一样，密码只保存在路由器上。

如果主服务器 2 分钟内无法连接，路由器会切换到备用服务器。备用服务器工作期间，路由器每 5 分钟检查一次主服务器是否有响应。连续两次检查成功后，切回主服务器。如果备用服务器也无法连接，路由器会在 2 分钟后再次尝试主服务器，如此轮流进行。每次切换时客户端都会重启，网络连接会中断几秒钟。备用服务器工作时，卡片上会显示「当前已连接备用服务器」。「删除备用服务器」按钮会将其连同密码一起删除。

同一卡片中的 **「连接延迟更低的服务器」** 开关会改变切回规则。路由器每半小时测量一次到两台服务器的延迟（从路由器发起 TCP 连接的时间），并切换到明显更快的服务器：快 30% 且至少 20 毫秒，连续两次测量。此时是否切回主服务器由测量决定，而服务器故障时仍会立即切换。

#### 速度与延迟

「服务器」页面上的 **「速度与延迟」** 卡片：「测量」按钮会显示到主服务器和备用服务器的延迟，以及在路由器上直连和经 VPN 的下载速度。一次测量最多下载 50 MB（来自 speed.cloudflare.com 的文件），约需半分钟。

#### 与服务器的连接中断时

- **启动时 DNS 无响应。** 如果服务器以域名指定，路由器在连接成功后会记住其 IP 地址。下次启动时，客户端会同时获得域名和这个备用地址。如果此时 DNS 无响应，客户端会按 IP 连接，而不会报错退出。
- **客户端显示「已连接」，但流量不通。** 隧道由看门狗监视。只要 TrustTunnel 客户端报告「已连接」，路由器每分钟就会经隧道发出一个简短的 HTTPS 请求：先请求 1.1.1.1，失败则请求 8.8.8.8。如果连续三次检查失败，路由器会重启客户端，但最多每 5 分钟一次。客户端自行重新连接服务器期间，看门狗不会干预。最近一次检查的结果显示在「诊断」中的「隧道看门狗」一行。
- **服务器不可用超过 2 分钟。** 如果设置了备用服务器，路由器会切换到它，见上文。

### 网站

在 **「哪些内容走 VPN」**卡片中选择模式：

- **「仅所选」**（推荐）。勾选的服务和你自己添加的网站走 VPN，其余照常访问。
- **「全部走 VPN」**。所有互联网流量都走 VPN，但「不走 VPN」列表中的网站和绕过封锁的网站除外。此时 IPv6 是关闭的，除非在「高级」中开启了[「IPv6 走 VPN」](#ipv6-走-vpn)。

如果只有一台设备需要全部流量走 VPN，请保留「仅所选」，并在[「设备」](#设备)页面为该设备开启「全部流量」。

**「服务」**：现成列表的磁贴，包括 YouTube、Instagram 和 Facebook、Discord、Telegram、ChatGPT 和 Google AI、TikTok、X 等。服务按组划分，并支持搜索。每个磁贴有三种状态：**VPN**（走 VPN）、**Zapret**（直连并绕过封锁）、**关闭**（与其他网站相同）。「俄罗斯封锁的全部网站」是一个大型综合列表；如果不知道该选什么，选它就够了。对于拥有自有网络的服务（Telegram、Discord、Meta 等），启用服务时会同时纳入其 IP 子网。「托管与 CDN」组包含整个托管服务商的网络，仅供专业人员使用。

**「网站列表」**：显示现成列表的更新时间、「更新」按钮和检查频率，详见[「网站列表」](#网站列表)。

自定义域名列表：每行一个地址，子域名自动包含在内：

- **「自定义网站走 VPN」**：服务中没有的网站。仅在「仅所选」模式下可用。
- **「绕过封锁的网站」**：不走 VPN，直连并使用 Zapret。即使关闭 VPN 也有效。
- **「不走 VPN」**：始终直连的网站，例如银行和政务服务网站。

**「其他网站」**（在「全部走 VPN」模式下为「不走 VPN 的网站」）：「直连」或「绕过封锁（Zapret）」。当 YouTube 或 Discord 不走 VPN 时卡顿或打不开，第二个选项会有帮助，详见[「绕过 DPI 封锁（Zapret）」](#绕过-dpi-封锁zapret)。绕过方法在「Zapret」页面中设置。

### 设备

- **「所有设备」**（推荐）：网站设置对整个家庭网络生效，新设备自动纳入。
- **「仅所选」**：例如只有电视和笔记本电脑。其他设备直接访问所有网站。需要的设备通过「走 VPN」开关勾选。

列表根据已连接的设备（DHCP 租约）生成：名称、MAC、IP 地址以及设备是否在线；列表较长时可以搜索。在「仅所选」模式下，铅笔按钮 **「重命名」**可以设置一个易懂的名称，该名称仅供你自己查看。重命名后的设备会自动被勾选。

**「全部流量」**：当「网站」页面选择「仅所选」模式时，每台设备旁都有这个开关。开启后，该设备的所有网站都走 VPN，而不仅是所选网站。「不走 VPN」和绕过封锁的网站对它同样有效。该开关在「所有设备」模式下也可用，例如电视需要全部流量走 VPN，而其他设备只让所选网站走 VPN。

### 概览

在服务器尚未配置时，「概览」页面上显示「连接服务器」卡片和「设置服务器」按钮。

此后页面的核心是 **「路由」**示意图：设备 → 路由器 → 路由（走 VPN、绕过封锁、直连），每条路由上标注对应的服务。生效的路由上有流动的圆点，未启用的路由以虚线表示；VPN 状态由路由器上的指示灯显示。「修改」链接指向「网站」页面。示意图上方的卡片只在出现问题时显示，并说明该如何处理。

面板顶部的 **VPN** 开关用于关闭 VPN：所有流量直连，但网站和设备的选择会保留，VPN 重新开启后恢复生效。VPN 关闭期间，绕过封锁的网站仍通过 Zapret 打开。但如果 Zapret 只对其他所有网站启用，它会随 VPN 一起关闭。

如果路由器未能应用最新配置，顶部会显示「设置未应用」并简要说明原因。此时路由器按之前的配置工作；如果是规则应用本身失败，则保持保护状态：在配置应用成功之前，VPN 列表中的网站无法打开。这种情况通常发生在隧道尚未建立时：隧道就绪后，路由器会每分钟自动重试一次。

页面底部显示网站列表的更新时间，以及指向「网站」页面（在那里管理列表）的 **「设置」**链接，详见[「网站列表」](#网站列表)。

下方是一天或一周的 **「流量」** 卡片：经过路由器 WAN 口的流量（全部互联网，包含加密的 VPN 流量）、其中隧道内的流量、每小时图表以及用量最大的设备。按设备统计来自固件自带的 trafficd 服务。路由器每 5 分钟采样一次并保留最近 7 天；`/data` 中的副本每小时更新一次，因此重启最多丢失一小时的数据。

### 自定义 DNS 记录

这是菜单中的独立页面（手机上位于「更多」中）。输入域名和家庭网络中的 IP 地址，点击「添加」：该域名及其所有子域名都将解析为此地址，例如用于运行 Traefik 的服务器。记录会自动保存。详见[「DNS」](#dns)。

### 诊断

这是菜单中的独立页面（手机上位于「更多」中）。**「检查」**按钮会在路由器上运行检查，耗时最多 20 秒，不会更改任何内容。检查项目包括：

- 自动启动：服务是否已在防火墙设置中注册，即路由器重启后是否会启动；以及路由器固件（如果不是 1.1.38 或最近更新过，会显示警告）；
- 路由器服务和 TrustTunnel 客户端：是否已连接到服务器、延迟多少、已连接多长时间，以及客户端版本；
- 隧道看门狗：最近一次经隧道的检查是什么时候、是否通过，以及看门狗在过去一小时内是否重启过客户端；
- 通过隧道访问互联网：路由器分别通过隧道和直连向 Cloudflare（1.1.1.1）查询自己的公网地址，两个地址应当不同；
- 进入隧道的路由、设备流量分类和地址集；
- 路由器的 DNS 以及已加载的 dnsmasq 配置；
- 其他网站的安全 DNS 和经 VPN 的加密 DNS（如已启用）；
- DPI 绕过（nfqws2）；
- 程序稳定性：TrustTunnel 客户端、nfqws2 和 DNS 代理在最近 10 分钟内是否崩溃过。重启三次及以上即显示「循环重启」（«перезапускаются по кругу»）。

当前不需要的检查项（例如 VPN 已关闭）会列在「未使用」一行中。各检查项中的详细信息由路由器返回，因此无论面板使用哪种语言，它们都是俄语。

**「检查网站」**会显示路由器通过哪条路径发送某个网站的流量（走 VPN、直连并绕过封锁或直连），以及该网站在这条路径上是否有响应。绕过封锁的网站由路由器直接检查：Zapret 处理的是设备的流量，而不是路由器自身的流量。检查不区分设备：「仅对所选设备」的规则按对所有设备生效显示。

**「日志」**：检查时服务、TrustTunnel 客户端和 Zapret 的最新日志记录；其中不包含密码。**「复制报告」**将检查结果和日志复制到剪贴板，便于附在问题反馈中。**「重启服务」**会重新启动 VPN 和 DPI 绕过并应用配置；网络连接会中断几秒钟。

### Zapret

这是菜单中的独立页面（手机上位于「更多」中）。顶部显示 DPI 绕过是否在运行以及处理哪些流量，「绕过哪些网站」按钮指向「网站」页面。下方是 **「所有网站」**和 **「YouTube」**的绕过方法：「自动」或手动选择某个现成方法；还有「恢复自动」按钮。再往下是 **「选择方法」**和 **「自动复查方法」**，详见[「绕过 DPI 封锁（Zapret）」](#绕过-dpi-封锁zapret)。

### 配置被手动修改时

只有当路由器上的配置符合面板的格式时，面板才会显示简单设置。通过 CLI（`mi-tt-ctl`）修改后，或者配置来自旧版面板时，会出现「设置已被手动修改」提示。只要你不做更改，路由器就按这些配置运行。**「转换为简单设置」**按钮会用面板的配置替换它们。

如果已保存的配置未通过校验，面板仍会加载它们并提供同一按钮；有问题的部分（例如 Zapret）会被替换为默认值。如果配置甚至无法解析，面板会显示「无法读取路由器上的设置」，并从头生成简单设置，此时需要重新粘贴 VPN 服务器。0.2.0 版本的 Zapret 配置（`multisplit`、`pos`、`tcp_ports`）会被读取为「自动」。

## 网站列表

服务列表取自 [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains) 项目。安装包内含列表快照，因此安装后即使没有互联网也能立即工作。

路由器会自动在 `raw.githubusercontent.com` 上检查更新，默认每天一次。列表在「网站」页面的 **「网站列表」**卡片中管理：显示列表的更新时间和最近一次检查的结果，**「更新」**按钮（立即检查，同时更新广告屏蔽列表），以及检查频率：每 6 小时、每天、每周或仅手动。每个下载的文件都会经过校验：看起来不像列表的响应，或条目数不到原来一半的列表，都不会被应用，继续使用原列表。新版本存放在 `/data/mi-lumruri/lists` 中并立即生效。如果没有网络连接，一小时后重试。如果 `/data` 已满或不可写，更新不会保存，错误会显示在「概览」和「网站列表」卡片中，同样一小时后重试。频率设为「手动」时，路由器不会自动检查，只在点击「更新」时检查。如果设置了[订阅链接](#服务器)，路由器会按同样的计划、通过同一按钮更新服务器参数。

安装新版本的安装包后，在下一次检查下载到新列表之前，使用该版本快照中的列表。

## 绕过 DPI 封锁（Zapret）

Zapret（来自 [zapret2](https://github.com/bol-van/zapret2) 的 nfqws2）会修改连接的前几个数据包，使运营商的设备无法识别所访问的网站。它不需要 VPN，只作用于直连的网站。VPN 列表中的网站不经过它。

**开箱即用。** 默认绕过方法为「自动（推荐）」。对每个网站，nfqws2 从第一个策略开始尝试，如果与该网站的连接连续三次失败，就切换到下一个策略。策略集取自 [Zapret-Manager](https://github.com/StressOzz/Zapret-Manager)：一套用于 HTTPS 网站的通用策略，以及分别用于 YouTube、Discord（包括 UDP 语音）和基于 QUIC 的 YouTube 的策略。

**「选择方法」**（位于「Zapret」页面，在 DPI 绕过处于使用中且配置已保存时可用）。路由器在不干扰网络的情况下单独测试各策略：在独立队列上运行单独的 nfqws2，并从专用端口发出 `curl` 测试请求。在此期间，家中设备继续按原有配置工作。测试目标为 YouTube、Discord 以及一组托管和 CDN 站点。先在不使用 Zapret 的情况下测试，再逐一测试通用策略集中的每个策略。如果 YouTube 在不使用 Zapret 时打不开，还会单独测试 YouTube 策略。服务器有响应（451 状态码除外）且响应未中断，即视为网站可以打开。挑选期间与正常运行时一样，Discord 网站由固定的 Discord 配置处理，因此不影响策略选择。挑选需要几分钟，进度显示在面板中。如果 Zapret 当前不生效（VPN 已关闭，或者所有设备的所有网站都无例外地走 VPN），则不显示该按钮，而是显示说明。

只有当最佳策略打开的网站比不使用 Zapret 时更多，才会应用它。应用后会再次验证；如果效果变差，则恢复之前的方法。面板会显示结果，例如「打开 47/54，不绕过——12」和「已应用最佳方式。」如果没有找到更好的方法，则不做更改，面板显示「未找到比不绕过更好的方式——保留原方式。」如果只找到了更好的 YouTube 方法，结果显示的是 YouTube 测试的数据。可以通过「Zapret」页面上的 **「恢复自动」**按钮恢复自动模式。如果挑选被中断（服务停止、重启），会恢复之前的方法。

**「自动复查方法」**（可选关闭、每天一次或每周一次）按计划重复同样的挑选过程，最早在路由器启动 10 分钟后进行。如果当前方法不再有效，就寻找新的方法；如果新方法更差，则保留原方法。最近一次自动复查的时间保存在 `/data` 中，因此重启不会打乱计划。

效果取决于运营商：没有过滤的地方，Zapret 不会带来任何变化；而过滤机制不同的地方，可能没有任何策略有效。

## 安全 DNS（DoH/DoT）

走 VPN 的网站本来就由路由器在隧道内解析。对于其他网站（包括绕过封锁的网站），DNS 查询默认以明文发往运营商的 DNS，运营商可能篡改应答，此时即使 Zapret 也无济于事。「高级」中的 **「其他网站的安全 DNS」**开关（关闭、DoH、DoT）会通过加密通道发送这些查询：

- **DoH**（DNS-over-HTTPS，端口 443）：推荐，看起来与普通 HTTPS 无异。服务器：Cloudflare、Google、AdGuard DNS、NextDNS（需要配置 ID，即个人账户中的 6 个字符）或自定义服务器。
- **DoT**（DNS-over-TLS，端口 853）：俄罗斯的运营商经常整体封锁该端口。这里还可以选择 Quad9（其 DoH 仅支持 HTTP/2，而安装包中没有 HTTP/2 支持）。

使用自定义服务器时，请填写 DoH 链接（`https://dns.example.com/dns-query`）或 DoT 服务器名称（`dns.example.com`），以及其 IP 地址（最多 4 个，用逗号分隔）：路由器按 IP 连接服务器，不依赖 DNS。

这一功能由路由器上的 `mi-tt-dns` 程序实现：dnsmasq 将查询发给它（`server=127.0.0.1#5453`、`no-resolv`），它再通过持久 TLS 连接直接按 IP 发往所选服务器。内置服务器（NextDNS 除外）还记录了 IPv6 地址作为备用路径：只有当所有 IPv4 地址都无响应时才会使用，因此没有 IPv6 的网络不会受到任何影响。走 VPN 的网站域名和自定义 DNS 记录的处理方式不变。TLS 使用 rustls 和 RustCrypto 加密库，根证书来自 Mozilla（webpki-roots）。

如果服务器不可用（被封锁、无网络连接，或启动后路由器时钟尚未同步导致证书校验失败），查询会暂时发往运营商的 DNS，否则整个互联网都会断开。在「高级」和「诊断」中可以看到有多少应答来自安全服务器、多少来自运营商，以及最近一次错误。

**经 VPN 的 DNS 加密。** 走 VPN 的网站的 DNS 查询本来就在隧道内传输，运营商看不到；只有从 VPN 服务器到 DNS 服务器这一段是明文。「经 VPN 网站的 DNS」区块中的 **「加密」**开关（普通、DoH、DoT）会把这一段也加密：第二个 `mi-tt-dns` 实例（端口 5454）将其连接绑定到隧道接口 `mitt0`，连接无法绕过隧道。它没有备用路径：如果隧道不可用，查询不会发往运营商，列表中的网站会等待 VPN 恢复。通常不需要加密，因为查询本来就在隧道内传输。可用于 Cloudflare、Google 和 AdGuard；Quad9 仅支持 DoT；NextDNS 和自定义地址仅支持普通模式（证书所需的服务器名称未知）。开关下方会显示有多少加密应答经隧道返回，或服务器为何无响应。

## 广告屏蔽

通过路由器的 DNS 实现：对于广告和跟踪器列表中的域名，dnsmasq 返回「域名不存在」（NXDOMAIN），请求不会发出。对所有从路由器获取 DNS 的设备生效；开启了自身「安全 DNS」（DoH）的浏览器会绕过它。

列表在「高级」中选择：**HaGeZi Light**（默认，约 9 万个域名，涵盖广告和跟踪器，几乎不影响网站）、**HaGeZi Normal**（约 20 万个，范围更广，偶尔可能影响个别网站），或 **自定义链接**：指向域名列表或 hosts 格式行（`0.0.0.0 域名`；`#` 为注释）的 https 链接，文件不超过 12 MiB。[HaGeZi](https://github.com/hagezi/dns-blocklists) 列表（GPL-3.0）采用「域名及其子域名」格式。

路由器会自动下载列表：启用或更换列表后立即下载，之后按与网站列表相同的频率更新；「网站」页面「网站列表」卡片中的「更新」按钮也会同时更新它。如果网站列表设为仅手动更新，广告列表在首次下载后也只通过这个按钮（或更换列表时）更新。下载失败时，一小时后重试。下载的列表会经过校验：HTML 页面、空响应，或无法解析的行超过 5% 的文件不会被应用，继续使用原列表；个别格式错误的行会被跳过。工作副本保存在 RAM 中，压缩副本（约 0.6–1.2 MB）保存在 `/data/mi-lumruri/adblock.list.gz`，因此重启后屏蔽立即生效。在「高级」中可以看到列表包含多少域名、更新时间，或未能更新的原因。

## DNS

设备仍从路由器获取 DNS：DHCP 和本地名称照常工作。对于列表中的域名，dnsmasq 会将应答中的地址加入规则集，路由器据此选择路由。

走 VPN 的网站域名由路由器通过单独的 DNS 服务器解析，发往该服务器的查询经隧道传输。服务器在 **「高级」**页面的「经 VPN 网站的 DNS」区块中选择：Cloudflare `1.1.1.1`（默认）、Quad9 `9.9.9.9`、Google `8.8.8.8`、AdGuard DNS `94.140.14.14`、NextDNS `45.90.28.0`，或「自定义地址」，可填写任意公网 IPv4 地址。使用 NextDNS 时，请在 NextDNS 账户中绑定你的 VPN 服务器 IP（Linked IP），否则过滤规则不会生效。其他域名由路由器照常解析，或通过[安全 DNS](#安全-dnsdohdot) 解析。

**自定义 DNS 记录**：域名及其所有子域名解析为指定的 IPv4 或 IPv6 地址，查询不会发出（dnsmasq `address=/домен/адрес`）。示例：`192.168.31.10` 上运行 Traefik 的家庭服务器和域名 `home.example.com`，一条记录即可覆盖 `traefik.home.example.com`、`pve.home.example.com` 等。对从路由器获取 DNS 的设备有效；记录仅在 Mi Lumruri 服务运行时生效。不要将这类域名加入走 VPN 或 Zapret 的网站列表：家庭服务器应当直连访问。

## IPv6 走 VPN

默认情况下 IPv6 不经过隧道：启用了 VPN、Zapret 或屏蔽的设备无法对外使用 IPv6，只通过 IPv4 访问。「高级」中的 **「IPv6 走 VPN」**开关会为全部流量走 VPN 的设备开放经隧道的 IPv6：

- 「全部走 VPN」模式下的整个网络或所选设备；
- 在「设备」页面开启了「全部流量」的设备。

仅当 VPN 服务器支持 IPv6 时才开启。家庭网络中的地址、link-local 和 multicast 不会进入隧道。如果隧道不可用，这些设备的 IPv6 流量会和其他流量一样等待（如果选择了「直接打开」，则直连）。

保持不变的部分：

- **所选网站不使用 IPv6。** dnsmasq 只把 IPv4 地址加入地址集，因此对于只有所选网站走 VPN 的设备，IPv6 仍然关闭。
- **例外的 IPv6 流量经隧道。** 对于全部流量走 VPN 的设备，「不走 VPN」中的网站和绕过封锁的网站通过 IPv4 直连，而通过 IPv6 则经隧道访问：路由器不按网站区分 IPv6 流量。

## 通过 CLI 精细配置

简单页面的底层是控制器的规则模型：来源（设备、网络、整个 LAN）× 目标（域名、子网、组、类别）× 动作（经 TrustTunnel、直连、直连并使用 Zapret、阻止）。面板根据各页面上的选择生成这些规则。诸如「机顶盒 → 阻止」之类的规则，或针对不同网络设置不同动作，只能通过 SSH 使用 `mi-tt-ctl` 设置；之后面板会显示「设置已被手动修改」。

## 限制

- **网站按 DNS 识别。** 列表中的域名只有在设备向路由器查询 DNS 时才生效。如果设备或浏览器启用了自身的 DoH/DoT（「安全 DNS」），路由器看不到查询，域名列表对该设备不起作用。服务的 IP 子网在这种情况下仍然有效。
- **域名同时匹配子域名。** 这是 dnsmasq 填充 ipset 集合的方式：`example.com` 也会匹配 `www.example.com`。
- **共享的 CDN IP 地址。** 路由按 DNS 应答中的 IP 地址选择。如果其他网站与之共用同一 CDN 地址，它也会走 VPN。
- **IPv6 仅用于「全部流量走 VPN」。** 列表中的网站只按 IPv4 匹配。启用了 VPN、Zapret 或屏蔽的设备无法对外使用 IPv6。例外是开启了[「IPv6 走 VPN」](#ipv6-走-vpn)时全部流量走 VPN 的设备：它们的 IPv6 流量全部经隧道，包括例外和绕过封锁的网站。这需要 VPN 服务器支持 IPv6。
- **防火墙重新加载。** 防火墙（fw3）完全重新加载时会清除所有 iptables 链。在 include 重新应用规则之前的约 1–2 秒内，流量直连。实验室中该窗口为 1.2 秒。
- **Zapret 挑选仅在没有 DPI 的实验室中测试过。** 在那里不使用 Zapret 时所有目标都能打开，挑选结果不出所料地为「未找到比不绕过更好的方式——保留原方式。」这些策略对具体运营商设备的效果，只能在路由器上实际测试才能知道。
- **列表从 GitHub 更新。** 如果无法直接访问 `raw.githubusercontent.com`，则使用安装包内置的列表或最近一次下载的列表。
- **同一时间只使用一台 TrustTunnel 服务器。** 原厂固件中只有一个空闲的标记位，因此流量只经一台服务器。备用服务器是替代主服务器启用，而不是与其同时启用，切换最多需要 2 分钟。
- **标记冲突。** 路由按标记位 `0x4000` 选择。如果固件规则使用了该位（例如多 WAN 时 mwan3 的 sticky 规则），应用会被拒绝，不做任何更改。
- **访客网络**不参与简单设置。

## 更新与回滚

**从面板更新**（自 0.4.0 版本起）。「高级」中有「更新」区块。路由器本身不会自动查找新版本：「检查」按钮会查询 GitHub 上的最新发布版本。路由器需要能访问 `api.github.com` 和 `github.com`。如果有更新的版本，会出现「更新到 …」按钮。路由器会自动下载安装包，将 SHA-256 与发布版本的 `SHA256SUMS` 文件核对，用已固定的密钥校验签名，然后重启服务。面板会消失约半分钟，配置会保留。重启后路由器会在最多 5 分钟内检查新版本是否正常工作：服务和面板已运行，并且如果更新前设置能无错误地应用，现在也必须能应用。否则路由器会自动恢复为之前的版本，面板显示「版本 … 未能正常工作，已恢复为 …」及原因。自动回滚适用于从 0.6.0 版本起通过面板进行的更新（检查由已安装的版本执行）。从 0.7.0 起，路由器每天自动检查一次新版本（也可以每周一次或仅手动，在同一区块中选择）。它只负责检查：有新版本时「高级」旁会出现标记，开启通知时还会收到 Telegram 消息。由你点击按钮安装。如果路由器上安装的是用你自己的密钥签名的自行构建版本，面板会提供「改用 GitHub 发布版并更新」。此时路由器会接受使用 GitHub 发布版本密钥（`e4a271890e5643ab`）签名的安装包并固定该密钥。面板不接受其他密钥。

**从电脑更新。** 更新时，重复快速安装，或者复制新的 TAR 并重复第 2 步直至配置登录之前。现有配置和第二因素会保留。版本存放在 `/data/mi-lumruri/releases`（或 `--store` 指定的目录）中：保留当前版本和上一版本，更早的版本会被删除。新版本需要约 4.5 MB 加 2 MiB 余量。如果空间不够，安装程序会删除旧版本；空间极少时则在不保留旧版本的情况下安装更新，此时无法回滚，详见[「`/data` 空间不足时」](#data-空间不足时)。

更新包必须使用与首次安装相同的密钥签名：首次安装时路由器会固定安装包的公钥，此后只接受用该密钥签名的安装包。GitHub 发布版本和 GitHub Actions 构建的安装包使用 CI 密钥签名，而在你自己电脑上构建的安装包使用 `.tools/keys/` 中你自己的密钥签名。如果在发布版本的安装之上安装自行构建的包，或者反之，安装程序会拒绝并显示两个指纹：「安装包使用其他密钥签名：已固定 …，安装包为 …」（«пакет подписан другим ключом: закреплён …, у пакета …»）。如需切换到其他密钥，请加上 `--trust-key` 参数和该提示中新密钥的指纹重新安装：

```sh
python install.py 192.168.31.1 --trust-key <指纹>
```

在路由器上的等效命令是 `sh install.sh install --trust-key=<指纹>`。配置、密码和密钥会保留。新密钥在安装后被固定，此后路由器只接受用它签名的安装包。GitHub 发布版本密钥的指纹写在每个发布版本的说明中。

当前固定的密钥可以在路由器上查看：

```sh
/tmp/mi-lumruri/bin/mi-tt-admin release key-fingerprint /data/mi-lumruri/keys/release.pub
```

返回结果是形如 `{"ok":true,"key_fingerprint":"…"}` 的一行。

要查看运行中服务的状态，请通过 SSH 执行：

```sh
sh /data/mi-lumruri/mitt-boot.sh status
```

回滚时，在已解压安装包中 `install.sh` 所在的目录下执行**一条**命令。如果重启后该目录已消失，请重新复制并解压 TAR。回滚无需运行安装。

```sh
sh install.sh rollback
```

安装第二个版本后，如果安装程序保留了之前的版本，即可回滚。否则该命令会提示「没有可回滚的上一版本」（«нет предыдущего релиза для отката»）。可以用 `sh install.sh status` 查看当前版本和上一版本。

## Telegram 通知

在「高级」→ **「Telegram 通知」** 中设置后，路由器会在以下情况通过 Telegram 通知你：

- 隧道中断（客户端超过 3 分钟未连接）以及恢复时，看门狗重启客户端时；
- 路由器切换到备用服务器或切回主服务器时；
- 有新版本安装包、更新已安装或已回滚时；
- TrustTunnel 订阅更新失败或更改了服务器参数时；
- 路由器启动时（默认关闭）。

设置方法：在 Telegram 中打开 @BotFather，发送 `/newbot` 并复制机器人令牌。给你的机器人发送任意一条消息，否则它无法给你发消息。通过 @userinfobot 获取你的数字 id（若用于群组，请把机器人加入群组；群组 id 以负号开头）。把令牌和 id 填入面板，勾选事件后点击「发送测试」。

隧道正常时消息经 VPN 发送，否则直连发送。如果 Telegram 无法访问，消息会在队列中等待并稍后发送（最多一天），因此「隧道中断」会在连接恢复后立即送达。令牌只保存在路由器上（`secrets.json`），面板不会显示。消息使用保存时面板的语言。

## 设置备份

在「高级」→ **「设置备份」**中，**「下载备份」**按钮会把文件 `mi-lumruri-backup-<日期>.json` 保存到电脑：设置、规则、设备、自定义 DNS 记录和自定义列表。服务器密码、订阅链接和面板登录（密码与第二因素）只有在打开 **「包含服务器密码和面板登录」**并设置备份密码（至少 8 个字符）时才会写入备份。路由器用备份密码通过 Argon2id 和 ChaCha20-Poly1305 加密这一部分；没有密码就无法读取或恢复。面板 TLS 密钥和发布签名密钥不包含在内：它们属于特定路由器。

**「从文件恢复…」**会用备份中的设置替换当前设置并立即应用。路由器会先完整检查备份；如果备份损坏、由更新的版本生成或其中的设置未通过检查，则不写入任何内容。如果备份包含密码，面板会要求输入备份密码；「不含密码」按钮只恢复设置。备份也可用于另一台 BE7000：在其上安装安装包、登录面板后恢复即可。

## 卸载

在已解压安装包中 `install.sh` 所在的目录下执行：

```sh
sh install.sh uninstall          # 保留 /data/mi-lumruri/etc 中的配置
sh install.sh uninstall --purge  # 连同配置一起删除
```

没有安装包时，可以通过 SSH 手动完成同样的操作：

```sh
sh /data/mi-lumruri/mitt-boot.sh stop
uci -q delete firewall.mitt
uci commit firewall
rm -rf /tmp/mi-lumruri /data/mi-lumruri
```

第一条命令会停止服务、移除路由规则，并从 dnsmasq 配置中移除 mi-lumruri 的文件。如果版本存放在 USB 存储设备上，`install.sh uninstall` 会自动删除它们；手动卸载时，还请删除传给 `--store` 的目录。

不加 `--purge` 时，`/data/mi-lumruri` 中会保留配置和已固定的签名密钥。此后安装使用其他密钥签名的安装包时，需要加上 `--trust-key` 参数。

## Xiaomi 固件更新之后

固件更新或防火墙设置重置可能会删除自动启动条目（`config include 'mitt'`）。服务运行时每 10 分钟检查一次该条目并自动恢复，「诊断」会在「自动启动」一行中显示。如果固件更新后路由器重启而服务没有启动，请重新开启 SSH（固件更新通常会关闭它）并执行：

```sh
sh /data/mi-lumruri/mitt-boot.sh repair
```

该命令会重新注册自动启动并启动服务。固件更新不会改动 `/data/mi-lumruri` 中的设置。安装包在 1.1.38 固件上测试；在其他固件上，「诊断」会在「路由器固件」一行中显示警告。

## 无法登录时

- **SSH 提示拒绝连接。** 请检查 LAN 地址以及当前固件上 SSH 是否可用。安装程序需要在 SSH 会话内运行。
- **安装程序提示空间不足。** 它会分别输出 `/data` 和 `/tmp` 所需的空间和可用空间。请用第 1 步中的命令检查这两个分区。如果是 `/data` 空间不足，请将版本迁移到 USB 存储设备，详见[「`/data` 空间不足时」](#data-空间不足时)。
- **安装程序提示「安装包签名或哈希校验未通过」（«подпись или хэши пакета не прошли проверку»）。** 安装包已损坏：请重新下载。如果安装程序提示「安装包使用其他密钥签名」（«пакет подписан другим ключом»），说明是在发布版本之上安装了自行构建的包，或者反之：请加上 `--trust-key` 重新安装，详见[「更新与回滚」](#更新与回滚)。
- **「概览」中一直显示「设置未应用」。** 打开「诊断」并点击「检查」，即可看到哪一部分不工作。路由器会将应用失败的报告保存到 `/tmp/mi-lumruri/run/apply.<标记>.fail.json`，可以与诊断报告一起附在问题反馈中。
- **重启后面板拒绝验证码。** 用 `date -u` 命令检查时间。等待时钟同步，或者使用一次性恢复码。已使用过的 TOTP 验证码不会再次被接受。
